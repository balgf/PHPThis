# Static analysis contract

PHPStan is part of the definition of valid PHPThis code, not an optional review tool.

Rules:

- Run PHPStan at `level: max` with the strict-rules extension.
- Keep `src/`, `example/`, `tests/`, `tools/`, and `autoload.php` free of findings.
- Do not create a PHPStan baseline.
- Do not add broad `ignoreErrors` patterns or weaken the configured level.
- Resolve `mixed` at an input boundary with validation and a typed value.
- For an ADR 021 input boundary, use PHT001 and maximum-level PHPStan to prove narrowing, the concrete command or request type, and any typed operation signature; use adversarial runtime tests for representations, bounds, deterministic generic errors, zero typed-seam calls when present, and zero operation-owned downstream work. ADR 042 adds no static diagnostic: structured request-body behavior tests own the complete structural phase, the default generic `400` versus exact application-owned generic `422` classification, mixed-failure property-order invariance, redaction, and separate query, header, route, transport, and non-input failures. Do not broaden PHT007 beyond canonical process-environment access.
- Add precise PHPDoc generics or array shapes only when native PHP cannot express the type.
- Prefer a tested custom PHPStan rule over a text-based exception for framework architecture.
- Give every PHPThis-owned rule a permanent `PHT` identifier and positive and negative fixtures.
- Make PHPThis-owned PHPStan findings non-ignorable; do not duplicate a rule already owned by PHPStan strict-rules.
- Enforce `PHT005` against application-owned `PDO` or PDO-subclass instantiation, calls resolving to the native `PDO::connect` factory, and first-class references to that factory. Resolve imports, aliases, fully qualified names, driver and named subclasses, statically typed PDO objects, and statically known `class-string<PDO>` values; keep the exemption confined to the real framework `Connection` file, and accept unrelated construction targets, unrelated `connect` methods, and PDO-subclass-overridden `connect` methods. Dynamically computed method names, callable arrays, `call_user_func`, reflection, and mixed target unions that do not resolve wholly to PDO construction or the native factory remain review limitations, not accepted escape hatches.
- Enforce `PHT006` at direct `Connection` call sites: the SQL argument must be a finite union of non-blank constant strings inferred by PHPStan itself. Reject argument unpacking and first-class or callable-array indirection. Do not accept a PHPDoc assertion, `literal-string`, sanitizer return type, path exception, or suppression as a substitute.
- Enforce `PHT008` after PHT006 at the same direct `Connection` call sites: inspect each finite SQL alternative independently and reject the call once when any exact case-sensitive portable named placeholder `:[A-Za-z_][A-Za-z0-9_]*` occurs more than once in one alternative. Use the fail-closed common lexical subset: ignore doubled-terminator single- and double-quoted segments; boundary-valid PostgreSQL `E'...'` escape strings; terminated non-nested block comments whose opener is neither `/*!` nor `/*+`; `--` only when the following byte is `0x00` through `0x20` or input ends; and structural multi-colon runs. Scan ambiguous SQLite brackets, backslash quote escapes in ordinary quotes, every backtick and `#` spelling, PostgreSQL dollar-quote-looking text, no-space `--`, MySQL executable or optimizer-hint block comments, nested block comments, and unterminated lexical forms fail-closed, and direct consumers to rewrite them unambiguously. Once one of those openers occurs outside an already ignored region, disable lexical exclusions for the rest of that alternative so nested quote- or comment-looking bytes cannot hide occurrences. Do not compare SQL with bindings, normalize case, parse positional placeholders or SQL syntax, select a dialect, or claim runtime rejection.
- Enforce `PHT007` in the consumer checker's structural stage: only direct `\getenv('EXACT_LITERAL_KEY')` reads, with one positional non-empty uppercase literal key of at most 128 bytes, and all reads in one application-owned PHP file. Reject unqualified direct calls, non-literal arguments, imports, literal callable indirection passed directly as a positional or named argument to supported native callback APIs under their built-in names, or held in local literal assignments later invoked directly before another assignment-operator occurrence, including through explicit closure/arrow capture, `$_ENV`, direct, imported, or aliased references to the global `INPUT_ENV` constant, literal `constant('INPUT_ENV')` and `constant('\\INPUT_ENV')` lookups, `putenv`, Apache environment access, indexed `$_SERVER`, and bare `$_SERVER` outside the exact `$coordinator->handle($_SERVER, $_GET, $_POST, $_FILES)` terminal-coordinator transport tuple. Dynamically constructed function or constant names, aliased native callback API names, application-defined, anonymous, or variable-dispatched callable consumers, reassigned callable variables, argument-unpacked callable values, local callable variables passed onward as callback arguments, and downstream misuse after that tuple remain review limitations. Variables implicitly reassigned through `foreach`, destructuring, or by-reference mutation may be conservatively reported from their earlier literal assignment. Application-defined unqualified functions or `Closure` classes deliberately sharing supported native callback names are conservatively treated as those native callbacks. Do not claim hard-coded-secret, secret-manager, redaction, validation, or deployment proof.
- Keep ADR 038's application-context consistency check ordinary and narrow: a direct canonical `PHPThis\Database\Connection::connect` call cannot coexist with an exact standalone `NOT_APPLICABLE(DATABASE)` line in `.ai/data.md`. It has no `PHT` identifier, must not treat an inline prose mention as the declaration, and does not connect to a database, inspect SQL, validate identities or effective privileges, or establish runtime readiness. Configuration-only scope without a connection call remains valid.
- Keep ADR 055's Composer/configuration consistency check ordinary and separate from PHT007. It correlates only valid canonical literal application input names with fail-conservative assignment and bounded recognized mutation spellings, reports only the input name, and does not parse shell quoting, referenced scripts, plugins, non-string callback shapes, dynamic or escaped names, profile completeness, ambient inherited authority, or lifecycle execution before the checker.
- Treat a `match` or other finite mapping from an external structural selector to reviewed code-owned SQL as valid only when PHPStan infers the final SQL as constant strings and the unknown branch rejects the request.
- Consumer applications run the installed `phpthis check` binary; they do not own a PHPStan configuration, baseline, or inline suppression path.
- Keep the `$_SESSION`, direct/imported native session call, and literal indirect-reference restrictions carried from Consumer Contract version 13 through current version 17 in the application checker's structural stage; dynamically obscured calls remain forbidden by contract, and this remains separate from Strict Profile v4.
- Under Consumer Contract v16, build one application-file manifest from every file whose extension compares case-insensitively as `.php` plus only the exact lowercase byte-zero direct and shebang extensionless forms. Classify every other regular file through the exact 4,096-byte prefix bound plus one-byte lookahead; reject broader direct or post-launcher BOM/ASCII-whitespace, case-insensitive long-tag, or `<?=` prefixes under unsupported suffixes and noncanonical extensionless names; fail conservatively for continuing ambiguous prefixes and unreadable non-`.php` files; and reject every symlink outside dependency and VCS exclusions before target-content inspection. Use the resulting manifest for syntax checks, the bounded report-only duplication advisory, and PHPStan; syntax and duplication must reuse one captured source read. Keep these as ordinary Contract v16 checker failures with no configurable ignore, Strict Profile rule, or `PHT` diagnostic.
- Keep the duplication signal advisory-only: no `PHT` identifier, validity effect, suppression, baseline, consumer configuration, automatic refactor, or required layout. Preserve its 48-token minimum, fixed work and debug-output caps, intentional relative-filename and line-only detail, PHP source-token non-disclosure, and continuation into PHPStan and application tests. Application paths must not contain secrets or customer data.
- Treat Consumer Contract v14's raw request-target/path byte rejection, carried into current Contract v17, and its carried-forward narrowest-route-type choice and canonical `positive-int`, `uuid`, `ulid`, and opaque `token` matching as runtime contract behavior, not part of PHT007 or PHT008. PHPStan preserves the matching `PathParameters` accessor return type; behavior tests prove rejection before routing or handler work, canonical acceptance, invalid-path `404` with zero handler and database work, and valid-path wrong-method `405`.

PHPStan proves static type and code-shape properties. It does not prove that bound data is semantically valid, a selector policy is complete, database/catalog/schema/attachment namespace selection is safe, a namespace or object control-or-ownership model is correct, database authority exists or is least-privileged, authority is active, release ordering is safe, statement counts are bounded, or SQL plans are acceptable. Runtime adversarial tests, exact-engine authority verification, query budgets, and database integration tests remain mandatory.

ADR 021, ADR 026, ADR 032, ADR 033, ADR 038, ADR 045, ADR 049, ADR 053, ADR 055, ADR 059, and ADR 060 add no `PHT` diagnostic. Consumer Contract v17 carries version 16 and Strict Profile v4 forward through ADR 060. ADR 038 adds one ordinary context-consistency failure, ADR 055 adds one ordinary Composer/configuration consistency failure, and ADR 059 adds ordinary bounded source-discovery failures, while ADR 060 changes runtime response-emission validity; their broader authority and deployment claims remain application context plus runtime evidence. The request-handler decorator, response-cookie, selected file-transfer profile, and pending-output boundaries remain contract and runtime behavior proved by explicit construction and application evidence, not part of PHT007 or PHT008.

ADR 022 likewise adds no diagnostic. PHT006 still proves only the finite constant-string SQL argument at direct calls; PHT008 separately proves only that every recognized named-placeholder occurrence in each finite alternative is distinct. Runtime tests own exact SQLite semantics, explicit parameter arrays, bounded category cardinalities, cursor traversal, tenant predicates, query counts, and proof limits. ADR 023 adds no diagnostic or core logging type, ADR 026 relies on native types plus runtime transport and file evidence, ADR 032 relies on fixed route declarations plus runtime behavior evidence, and ADR 033 relies on explicit route construction plus behavior evidence. PHT007 remains limited to the configuration access boundary.
