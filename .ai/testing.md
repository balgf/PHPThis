# Testing contract

The framework repository uses PHPUnit 13 as a maintainer-only development runner. `tests/run.php` is the explicit ordered loader and owns the duplicate-checked registry of exactly 181 named behaviors. Behavior definitions live in the focused concern files explicitly required there; the six definitions formerly embedded in the loader now live in `tests/composition.php`, `tests/http-boundary.php`, `tests/routing.php`, `tests/input-projection.php`, `tests/crud.php`, and `tests/database-boundary.php`. Narrowly shared test support lives in `tests/request-reader-support.php`, `tests/process-support.php`, and `tests/create-user-support.php`. `tests/behavior-names.txt` locks the complete behavior order, and `tests/FrameworkBehaviorTest.php` exposes each behavior as an independently selectable PHPUnit data set in one coherent group. Run the canonical suite with `composer test`; append PHPUnit options after `--`, for example `composer test -- --filter 'exact behavior name'` or `composer test -- --group routing`. PHPUnit writes JUnit output under `.phpunit.cache/`, and `composer test:coverage` adds report-only source coverage with no percentage threshold. Local coverage requires PCOV or Xdebug; framework CI supplies PCOV.

`tools/guardrails.php` is likewise a small explicit ordered entrypoint over exactly five concern modules under `tools/guardrails/`: repository, context, boundaries, operations, and distribution. Every module returns its failures, the entrypoint preserves their fixed aggregate order and output, and each concern keeps its markers and controls local. Do not add discovery, a rule registry, a container, a configuration language, or a shared content cache merely to organize this maintainer command.

The maintainer-only PHPThis Agent Evaluation Kit lives under `tools/agent-evaluation/` and is not distributed with the framework package. `tools/agent-evaluation.php` is its small explicit ordered entrypoint over exactly four cohesive modules: `support.php`, `tasks.php`, `run.php`, and `score.php`. The entrypoint uses fixed requires; do not add discovery, a registry, dependency injection, or a second command path merely to organize this maintainer tool. Its ordered task inventory, versioned JSON schemas, frozen prompt hashes, public scorer hashes, run-record validator, score-record validator, and negative controls remain the unchanged v0.1 data contract.

ADR 048 separately accepts `tools/agent-evaluation-controller.php` as the small ordered v0.2 entrypoint. It requires exactly `contract.php`, `workspace.php`, `process.php`, `codex.php`, `scoring.php`, and `controller.php` from `tools/agent-evaluation-controller/` in that order; only `process.php` owns process-execution primitives. Its deterministic test-only `fake-codex` runner must traverse `prepare -> generate -> freeze -> score -> validate -> retain -> cleanup` in that order and cover source and dependency mismatch, phase-order violations, generation failure and limit exhaustion, workspace escape, protected and unlisted paths, symlinks and special files, executable-bit and change-limit violations, post-freeze mutation, scorer timing and integrity, run/score inconsistency, retained-artifact bounds, original-process-group cleanup, and cleanup-failure precedence. Its fixed application-check and public-scorer processes exercise only those command slots, outputs, bounds, and failures; they do not prove the real candidate gate or scorer passed. The native fake cannot prove termination of a child that escapes into another process session; that claim belongs only to the future OCI container-destruction evidence. `tools/test-agent-evaluation-controller.php` is the focused self-test, and `test:agent-evaluation-controller` follows `test:agent-evaluation` and precedes the profile stage in `composer check`. The complete gate uses only synthetic fixtures; it performs no paid model or external request, needs no credential or OCI engine, and executes no AI-authored candidate code. The fake proves controller behavior, not real containment.

The repository does not call a model provider or execute AI-authored candidate code as part of `composer check`.

The stable `AGENT_EVALUATION_CONTROLLER_OCI_ONLY`, `AGENT_EVALUATION_CONTROLLER_FAKE_RUNNER_CI_ONLY`, and `AGENT_EVALUATION_CONTROLLER_NO_NATIVE_FALLBACK` markers lock the execution boundary. The only accepted future real adapter is `codex-exec`. It must remain opt-in and fail closed unless every ADR 048 preflight proves a Docker-compatible OCI image pinned by digest, non-root identity, read-only root, dropped capabilities, no privilege escalation, PID isolation and count, finite CPU, memory, temporary-disk, wall, output, and token limits, candidate-only writable storage, read-only prepared dependencies, proxy-only generation network, a host-side `responses-api-run-proxy` that alone holds the provider credential and enforces model and token quota, post-freeze scorer introduction, no-network scoring, and verified descendant and resource cleanup. There is no native macOS, `sandbox-exec`, direct-host, arbitrary-shell, discovered-runner, or second-runner fallback. The initial v0.2 implementation does not implement or exercise `codex-exec`. The public `change.simple-ping` task retains `comparative_claims: false`; official comparison additionally needs an external scorer unavailable during generation, repeated identical-condition trials, and human semantic review.

PHPUnit belongs only to this repository's root `require-dev`. It is not a framework runtime dependency, exported package file, Consumer Contract requirement, or skeleton choice. Applications continue to own their test library, runner, organization, and `composer test` implementation; PHPThis requires executable behavior evidence, not PHPUnit specifically.

New or touched comparisons use native PHPUnit assertions when both expected and actual values exist; do not invent a synthetic difference around a legacy exception.
