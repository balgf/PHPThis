# Application CLI and scheduler contract

Start ordinary command work with [Application CLI and scheduler](../docs/cli.md) and this current guide. Read [ADR 025](../docs/decisions/025-application-owned-explicit-cli-and-scheduler.md) only when reviewing or changing its CLI and scheduler decision, and [ADR 028](../docs/decisions/028-application-owned-redis-cache-and-schedule-lease.md) only when reviewing or changing its Redis overlap decision. For a migration command, enter `.ai/migrations.md` and [Explicit application migrations](../docs/migrations.md); read [ADR 043](../docs/decisions/043-engine-specific-application-migration-invariants.md) only when reviewing or changing its migration-invariants decision. PHPThis provides no core CLI command, command map, argument parser, scheduler, lock, lease, daemon, or process manager. Framework `bin/phpthis` remains the installed `check` boundary only.

Rules:

- Give the application one explicitly named console entrypoint and one finite code-owned command map. Construct each command and dependency manually; do not discover commands, resolve a class name from input, use a service container, scan files, or install a generic console or scheduler facade.
- Parse `$argv` once at the console boundary. Reject an unknown command separately from invalid, duplicate, misplaced, oversized, or unsupported arguments before application I/O. Narrow accepted values into command-specific typed values; never pass a raw argument array into operation behavior.
- Record one closed exit contract. The accepted pattern uses `0` for every recorded expected command outcome; the current scheduled pass includes `not_due` and `overlap_skipped`. It uses `2` for unknown command or invalid arguments and `1` for operational or unexpected failure.
- Emit exactly one newline-terminated JSON object to stdout for exit `0`, with stderr empty. Emit exactly one generic newline-terminated JSON error to stderr for exits `1` or `2`, with stdout empty. Keep key order and finite outcome vocabulary stable. The current `schedule:run` success adds a bounded `coordination` list after `command` and `outcome`; a Redis operational failure adds its finite list after `error: command_failed`. Never emit submitted arguments, paths, Redis endpoints, keys, values, owner tokens, raw replies, DSNs, credentials, exception classes or messages, stacks, SQL, bindings, envelopes, payloads, or domain values.
- Compose fresh command-scoped connections, budgets, traces, operations, and other adopted invocation state for every process invocation. A scheduled pass additionally receives its explicit clock. HTTP and CLI may share immutable configuration and explicit application construction code, but never a mutable request object, request correlation, session lifecycle, connection, budget, trace, or other request-scoped state.
- Keep `jobs:run-one` a direct one-pass call to the adopted application-owned job operation. It handles zero or one delivery and exits. Do not add polling, recursion, subprocess dispatch, an internal supervisor, or another spelling for that operation.
- When a scheduled pass is adopted, keep it cron-friendly and one-pass. Record its explicit clock, timezone, finite cadence, missed-run, catch-up, repeated-in-slot, supervisor, timeout, overlap, topology, release, crash, and coordination-limit policy. A due pass may invoke the exact same in-process operation as the direct command; do not create a second handler or enqueue path. A console with no scheduled pass records those schedule-only facts as not applicable.
- Make scheduler preflight order explicit. The current example evaluates its injected clock and cadence before database-path inspection, Redis, PDO, token generation, SQL, or job work. A non-due pass returns `not_due` with empty coordination and is not a dependency-readiness result; a due pass resolves its database path before Redis coordination.
- Guard the current example's scheduled pass with its application-private Redis lease: one fresh owner token, nonblocking `SET NX PX` acquisition, fixed owner-checking renewal and release scripts, finite TTL and timeouts, and a separate `noeviction` lease process. The proof defaults cache to `127.0.0.1:6379/0` and lease to `127.0.0.1:6380/0`; logical databases on one process are not separation. Fail closed on Redis operation errors, retain their bounded coordination evidence, and treat contention as an explicit expected outcome. Do not add retry, waiting, a renewal loop, a fencing-token claim, or a generic distributed-lock API. A different scheduled application may retain ADR 025's same-host `flock` only when its recorded topology is single-host. The accepted Redis lease does not deduplicate sequential invocations, replace job idempotency, fence work after expiry, survive every partition, or prove an external effect executes once.
- Keep all operational commands, argument policies, output schemas, locks, clocks, schedules, side effects, and tests application-owned. Do not add them to PHPThis core or route them through `vendor/bin/phpthis`.
- Keep every migration command finite and explicit on the sole application console. Record and prove its writer coordination or serialization in `.ai/migrations.md` under ADR 043 rather than treating it as scheduler overlap. The current ADR 027 SQLite example keeps `database:migrate` as its sole migration spelling, acquires its application-private nonblocking same-host lock before database work, executes the finite unrolled SQLite manifest once, and exits with `applied` or `up_to_date`. Do not invoke a migration command from HTTP startup, dependency hooks, the scheduler, or another command.

Tests must execute the real console in fresh subprocesses and prove every adopted finite command and expected outcome, unknown-command and invalid-argument handling, operational and unexpected failures, stdout/stderr exclusivity and exact bytes, finite argument bounds, pre-I/O rejection, one-pass resource bounds, fresh composition, redaction, and no hidden second console or execution path. When a scheduled pass is adopted, additionally prove explicit-clock cadence boundaries, its recorded preflight order, not-due exclusion from database-path and external I/O when cadence is the first gate, the recorded overlap mechanism and cleanup or release, and every missed-run, catch-up, repeated-slot, supervisor, and topology limit; when ADR 028 is adopted, also prove Redis contention, renewal, stale-owner, safe-release, outage, termination, and expiry-recovery behavior. A migration command instead proves its engine- and topology-specific coordination, outcomes, and failures through `.ai/migrations.md`; only the ADR 027 SQLite reference proof inherits `applied`, `up_to_date`, and same-host `flock` evidence.
