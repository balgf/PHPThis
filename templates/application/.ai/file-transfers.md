Before adoption, read installed `vendor/phpthis/framework/docs/file-transfers/README.md`. Forward the runtime's parsed form and file values at the front controller, then opt into multipart with one finite total request limit. Record a stricter operation-owned per-file limit when applicable.

Pre-PHP controls are dated effective facts from the selected web SAPI, server, and proxy, not merely intended configuration. Include connection and header/body limits, name the first layer expected to reject each overflow, and prove its externally observable status/body/header/connection behavior. `max_multipart_body_parts` bounds total raw multipart resource use; it does not prove that repeated scalar field names were rejected. Cardinality at `RequestReader` applies to PHP-normalized file entries. If that ambiguity is unsuitable, record and test one upstream duplicate-name rule or seek a separately accepted bounded raw parser.

For a protected upload, keep `authenticate -> resolve tenant when applicable -> authorize upload -> validate CSRF when applicable -> rate/concurrency admission -> atomic quota reservation -> storage` visible and prove each failure prevents every later step. A protected download authorizes its named action before lookup when existence is confidential. `SameSite`, an opaque identifier, a route token, and `LocalFileBody` are not permission. Record public, stateless, non-browser, tenant-free, owner-free, and CSRF-free facts explicitly when applicable.

Treat every client filename, path, extension, and media type as untrusted input. `OPAQUE_BYTES` uses fixed code-owned stored/download names and only an `application/octet-stream` attachment with `nosniff`, explicit cache and recorded authentication/authorization; it does not certify content safety. `INSPECTED_CONTENT` treats a successful scan as one bounded signal for the exact inspection definition, not universal safety proof; pending, scanner-error, rejected, and quarantined content remains non-serving until accepted promotion, and every definition change owns retained-byte reinspection or explicit no-reinspection. An external inspector additionally requires exact third-party processing, retention, residency, credential, transport, and failure decisions. Generate retained identifiers and names on the server and bind them to applicable tenant, owner/principal, and named authorization action. The PHP temporary path is request-scoped input only and never persisted, enqueued, logged, traced, or reused; durable work receives only the destination/reference established after the move. Use a dedicated effective web-SAPI `upload_tmp_dir` with exact ACL or `NONE`, no-execute/non-public mount policy, monitoring, and stale cleanup. Deployment pre-creates the separate durable root before HTTP handling; the non-root request identity cannot and need not create or repair it. Post-move publication requires a fresh regular non-symlink type, exact accepted byte-count, and permissions check. For the current path-only response profile, the selected pathname and bytes must remain immutable under exclusive-writer authority from authorized selection through completed emission. An integrity claim additionally owns an exact digest lifecycle, but that digest is only additional evidence and cannot replace the mandatory storage invariant. An identity-bound body, open-handle body, or different response primitive requires a separately accepted core/response decision. Give stale temporary cleanup, quota reconciliation, and deletion propagation one named finite path each. Retries and duplicate requests never imply idempotency without a recorded key, ownership, expiry, collision, response, and evidence; an ambiguous client response after completion has an explicit outcome. Do not introduce generic auth, quota, scanner, upload, storage, filesystem, lifecycle, or checker APIs.

A download owns explicit framing, cache, sniffing, disposition, and range behavior; application response decoration preserves any selected file body. The framework emitter checks regular-file type and exact expected size before headers, then makes one sequential pass of at most 8,192 bytes per read. It either echoes the declared count or throws without retry or post-start replacement. It does not guarantee immutable content after `fstat`, integrity, client receipt, network completion, durable delivery, or external buffering; the application/deployment must enforce the mandatory path-only immutability/exclusive-writer invariant throughout emission.

Application-owned tests exercise the real web-SAPI boundary; exact and overflow limits at their actual owners; normalized and raw-duplicate policy; every runtime status; provenance; request-policy and CSRF order; temporary/durable root authority; quota concurrency; lifecycle; content posture; cleanup; metadata/path redaction; missing files; exact downloaded bytes and headers; range behavior; pre-header failure; and bounded application memory. Integration and deployment evidence proves effective ingress, filesystem, scanner/parser, supervisor, quota, cleanup, topology, and buffering behavior. Static context checks prove only that this authoritative record and its finite markers exist and route into the complete application gate.
