If that ambiguity is unsuitable, record and test one upstream duplicate-name rule or seek a separately accepted bounded raw parser.

For a protected upload, keep `authenticate -> resolve tenant when applicable -> authorize upload -> validate CSRF when applicable -> rate/concurrency admission -> atomic quota reservation -> storage` visible and prove each failure prevents every later step. A protected download authorizes its named action before lookup when existence is confidential. `SameSite`, an opaque identifier, a route token, and `LocalFileBody` are not permission. Record public, stateless, non-browser, tenant-free, owner-free, and CSRF-free facts explicitly when applicable.

Treat every client filename, path, extension, and media type as untrusted input. `OPAQUE_BYTES` uses fixed code-owned stored/download names and only an `application/octet-stream` attachment, explicit cache and recorded authentication/authorization; `LOCAL_ADR026` requires `nosniff`, while `AMAZON_S3_ADR053` accepts its absence only on the separate direct-S3 response. Neither certifies content safety. `INSPECTED_CONTENT` treats a successful scan as one bounded signal for the exact inspection definition, not universal safety proof; pending, scanner-error, rejected, and quarantined content remains non-serving until accepted promotion, and every definition change owns retained-byte reinspection or explicit no-reinspection. An external inspector additionally requires exact third-party processing, retention, residency, credential, transport, and failure decisions. Generate retained identifiers and names on the server and bind them to applicable tenant, owner/principal, and named authorization action. The PHP temporary path is request-scoped input only and never persisted, enqueued, logged, traced, or reused; durable work receives only the destination/reference established by the selected storage operation. Use a dedicated effective web-SAPI `upload_tmp_dir` with exact ACL or `NONE`, no-execute/non-public mount policy, monitoring, and stale cleanup. `LOCAL_ADR026` additionally pre-creates the separate durable root before HTTP handling, prevents the non-root request identity from creating or repairing it, rechecks the post-move file, and preserves selected pathname/byte immutability through completed local emission. `AMAZON_S3_ADR053` instead uses its exact bucket/key/version/KMS/lifecycle ownership and reconciliation contract. An integrity claim owns an exact digest lifecycle. Give stale temporary cleanup, quota reconciliation, and deletion propagation one named finite path each. Retries and duplicate requests never imply idempotency without a recorded key, ownership, expiry, collision, response, and evidence; an ambiguous client response after completion has an explicit outcome. Do not introduce generic auth, quota, scanner, upload, storage, filesystem, lifecycle, or checker APIs.

A download owns explicit framing, cache, sniffing, disposition, and range behavior. Under `LOCAL_ADR026`, application response decoration preserves the selected local-file body. At emitter entry, already-sent headers or pending bytes in any active PHP-managed output-buffer level fail as `ResponseEmissionFailed(true)` before file access or response output; all-empty active buffers remain valid, and the application removes early output at its owner rather than cleaning or incorporating it. The emitter then checks regular-file type and exact expected size before headers and makes one sequential pass of at most 8,192 bytes per read. It either echoes the declared count or throws without retry or post-start replacement. It does not guarantee custom output-handler private state, later output, immutable content after `fstat`, integrity, client receipt, network completion, durable delivery, or external buffering; the local application/deployment must enforce the mandatory path-only immutability/exclusive-writer invariant throughout emission. Under `AMAZON_S3_ADR053`, the application instead proves its empty `303`, exact pre-signed URL, and recorded range, reuse, expiry, and client-delivery limits.
