# One required entrypoint per audience

Status: accepted

On 2026-10-09 (Asia/Manila), the accountable maintainer approved the concrete Issue #84 proposal: one required `AGENTS.md` for framework maintainers and one for consuming applications, followed by the relevant current guide, source and tests. Existing applications adopt the change explicitly.

## Decision

`AGENTS.md` owns universal authority, safety, coding constraints, task routing and the completion workflow. Other context files remain available and required where the existing application inventory requires them; rule and workflow files may be compatibility pointers. The full Consumer Contract is a conditional read for installation, context adoption, upgrades and conflicts, and remains binding in ordinary work through the current concern guides.

First contributors and tasks involving product vocabulary, invariants or ownership read project facts and applicable architecture records. Database setup reaches configuration scope safeguards before external action. Preserve stronger application rules and unresolved decisions when deliberately adopting the shorter route; installing a dependency never changes application instructions.

Current guidance links to historical evaluations, calibrations and release receipts at their existing owners. Keep frozen fixtures, prompts, hashes, attempts and tagged history intact. Measure universal and complete task reading separately at a named revision using ordered file inventories and words/bytes. Counts are observations, not validity thresholds or token measurements.

This partially supersedes ADR 044 and ADR 058 only for their mandatory read order and universal instruction ownership. The complete simple-endpoint definition, inline dependency-free construction exception, four-file task-specific metric, human authority, safety, diagnostics and behavior evidence remain unchanged. Any needed extra project or concern reading is reported and disqualifies a four-file claim.

Consumer Contract 18, Strict Profile 4, PHT001–PHT008, runtime APIs, dependencies and application validity are unchanged. There is no context loader, reporting command, new evaluation protocol or automatic migration.

## Verification and reconsideration

Review explanation, endpoint, database, security-sensitive and unfamiliar-contributor routes. Check current/template/skeleton/installed distribution together, then run the complete `composer check` gate. Route checks establish reachability; humans review meaning. Reconsider if a real task loses a required decision or safety boundary, or repeated routes require irrelevant universal context. Repair the relevant owner before expanding universal reading.
