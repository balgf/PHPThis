# Guardrails

`php tools/guardrails.php` currently enforces repository-level invariants without third-party packages:

- every PHP file declares strict types;
- every named repository class is final (`PHT002`);
- magic methods other than constructors are absent;
- dangerous dynamic mechanisms such as `eval` and variable variables are absent;
- calls to `selectAllRows`, `selectOneRow`, and `executeStatement` do not occur inside loop headers or bodies (`PHT003`);
- exact-literal and bounded multiple-typed route lookup do not scan declared routes or index collections at request time; bounded request-path segment traversal remains permitted;
- the accepted typed-route decisions including ADR 032, immutable type-specific delivery for the four fixed types, exact-literal precedence, canonical token/UUID/ULID bounds, the two-parameter limit, no type fallback, and overlap rejection remain covered by repository tests;
- accepted ADR 033, introduced under Consumer Contract version 9 and carried forward by current Consumer Contract version 10 and Strict Profile version 3, application and skeleton guidance, and installed-consumer evidence preserve the optional route-local application-owned request-handler decorator boundary: exactly one downstream handler, zero-or-one same-request invocation, unchanged exception propagation, explicit immutable response preservation, bounded named I/O, visible nesting, and no generic or framework middleware mechanism;
- accepted ADR 034, the WebSocket review profile, project-owned AI routes, and package inventory preserve the optional application-owned WebSocket boundary while rejecting framework runtime paths, proof-only runtime dependencies, HTTP adaptation, generic real-time mechanisms, and any new checker requirement for `.ai/websockets.md`;
- accepted ADR 036, Consumer Contract version 10, Strict Profile version 3, PHT007 fixtures, required application configuration context, package inventory, root and skeleton `.env` ignore rules, and installed-consumer evidence preserve one application-owned typed configuration boundary without adding framework application/deployment configuration runtime or dotenv dependency;
- accepted ADR 037, its early application scope gate, configuration-only typed-boundary meaning, external-I/O prohibition before approval, conditional process profiles, package inventory, and installed-consumer guidance-distribution evidence remain present without adding database setup runtime or a new diagnostic; the guard also rejects the reviewed unconditional composition, elevated-profile, and template-placeholder wording;
- PHP runtime-input superglobals are read only in the example and skeleton front controllers, `$_SESSION` is read only in `src/Session/SessionLifecycle.php`, and consumer PHT007 rejects `$_ENV` plus indexed `$_SERVER`;
- native `session_*` calls occur only in `SessionLifecycle`, with the same restriction enforced in consuming applications;
- the consumer contract, installed knowledge map, and every required application context template file remain present;
- the optional CRUD reference profile, its accepted decision, and its AI routing context remain present;
- the application-owned typed-input decision, canonical parser-to-command-to-use-case path, adversarial example proof, application-context fields, and explicit health-only `NOT_APPLICABLE(INPUT)` state remain present;
- the application-owned finite-data-path decision, compact example AI context, four document-list boundaries, eight complete raw SQLite statements, explicit parameter arrays, finite order/cursor/category behavior, constant query evidence, and SQLite-only claim remain present;
- the application-owned SQLite durable-job decision, AI routes, new-project and adoption context, Contract-v6 checker compatibility, bounded envelope and finite dispatch, same-transaction publication, one-shot worker, fenced transitions, retries, dead letters, subprocess crash proof, idempotent effect, redaction, and explicit unsupported boundary remain present;
- the cache policy guide, policy-before-mechanism decision, application-owned Redis proof decision, AI routes, required HTTP policy fields, explicit server-side adoption or not-applicable fields, cache-aside boundaries, owner-token lease boundaries, and unsupported framework API remain present;
- the vision, consumer contract, skeleton, and application template preserve the AI authoring and human-accountability route;
- the canonical check and CI workflow preserve the SQLite, MySQL, and PostgreSQL PDO transport certification path;
- the SQL data-versus-finite-structure decision, Consumer Contract version 10, Strict Profile version 3, application authority template, and PHT006 implementation remain present;
- the bounded file-transfer decision, typed one-file multipart request, explicit application storage ownership, concrete local-file response, exact framing, fixed-chunk emission, real-SAPI evidence, AI routes, and explicit exclusions remain present;
- the current seven-step SQLite migration manifest, 23-statement ceiling, forward `account_users` identity-separation migration, unrolled calls, checksums, and no-backfill evidence remain present;
- the Alpha 2 consumer-profile exit ledger, integrated account-scoped mutation, direct SQL-policy and rollback tests, exact PHP 8.4 Composer constraint and CI row, package inventory, and permanent no-magic boundaries remain present;
- Markdown files outnumber PHP files;
- core source stays within ADR 032's accepted, narrowly scoped 2,600-physical-line ceiling;
- PHPStan baseline files are absent;
- `phpstan.neon` keeps strict-rules, every strict rule, and the PHPThis extension enabled without `ignoreErrors`.

Runtime query budgets enforce a separate limit before each statement executes. Request-scoped query traces add bounded, redacted evidence about executed statement shapes, repetition, timing, and failures.

The earlier cap increases remain scoped to ADR 015's explicit cookie/native-session slice and ADR 017's bounded trailing positive-integer routing slice. ADR 019 raised the Alpha 2 ceiling from 2,050 to 2,300 only for at most two full-segment `positive-int` or bounded `token` parameters, deterministic state indexing, type-specific immutable delivery, and required overlap and scaling evidence. ADR 026 raised that ceiling from 2,300 to 2,500 only for the typed one-file multipart boundary, concrete local-file response, exact framing, and fixed-chunk emitter; its accepted 2,495-line implementation remains historical evidence. ADR 032 raises the current-checkout ceiling from 2,500 to 2,600 only for fixed lowercase UUID/ULID recognition and immutable type-specific delivery. The implementation now occupies 2,593 lines after one `SensitiveParameter` declaration and leaves seven lines that authorize no fifth route type, fallback, binding behavior, configuration runtime, or adjacent request mechanism. ADR 033 adds no core line and no additional margin. Repository checks retain the accepted decisions and knowledge routes, the accepted but unreleased post-Alpha-4 Consumer Contract version 10 and Strict Profile version 3 working-tree authority, the application context fields that keep identifier meaning and configuration authority application-owned, and the route-local decorator ownership fields.

The WebSocket guard retains only the accepted documentation and context boundary. It checks the application-owned review profile, the separate process and HTTP-type exclusion, explicit resource and lifecycle decisions, the three exported package artifacts, and the two project-owned context defaults. It rejects reviewed WebSocket, real-time, event-loop, daemon, supervisor, broadcaster, pub/sub, and channel names under framework `src/`, rejects the proof consumer's runtime dependencies from framework and skeleton Composer requirements, and keeps `.ai/websockets.md` optional under current Contract version 10 as well as its originating Contract version 9. The check does not inspect arbitrary consumer WebSocket semantics, run a protocol server, certify a third-party runtime, or make the independent consumer's numeric limits universal.

The routing lookup check follows direct helper calls from `Router::match` and `Router::allowedMethodsForPath`. It permits only the reviewed traversal of path segments obtained locally from the bounded request path. It rejects other explicit loops and reviewed array-traversal functions anywhere in that reachable method graph, including a loop over a compiled index, while leaving constructor-only indexing helpers outside it. Stable fixtures prove that bounded path-segment traversal and construction-time indexing pass while route-list, index, helper, `array_find`, and `array_filter` traversal in lookup-reachable code fail.

The cache guard retains the policy-before-mechanism authority and one application-owned Redis proof, not a framework cache implementation. It keeps the absence of a generic framework cache or lease explicit, preserves separate HTTP and application data-cache decisions, requires the health-only skeleton to record its explicit `no-store` response policy, and leaves server-side caching not applicable there. Framework and behavior tests cover explicit `no-store` on the current 404, 405, skeleton, and example paths; the generic 500 and protected application outcomes additionally use `private`. Arbitrary application responses remain application-owned. ADR 028's example proof pins one tenant-safe versioned cache-aside read, visible post-commit invalidation, bounded stale-refill policy, separate cache and lease topology, finite owner-token lifecycle, redacted evidence, and documented failure limits. It does not certify a generic backend, production topology, failover, fencing, or exactly-once behavior.

The permanent framework-mechanism path check applies only to PHPThis package paths under `src/`. It rejects exact mechanism directories and reviewed CamelCase filename suffixes for ORM/model/repository/facade/discovery/observer/scope/container patterns, plus explicit query-builder, binding-helper, placeholder-helper, autowiring, generic application/deployment/runtime configuration classes and paths, configuration bags, repositories, services, helpers, facades, providers, readers, secret managers, and dotenv loaders. Passing names such as `Transform`, `Telescope`, and the narrowly scoped session value `SessionConfiguration` are fixtures so substrings and legitimate concern-specific values are not mistaken for hidden mechanisms. This is a deterministic path heuristic, not semantic proof: aliases or differently named hidden behavior remain forbidden by the contract and require human review, while example application paths are deliberately outside this package-path check.

The configuration guard also pins exact `.env`, `.env.*`, and `!.env.example` entries in both the framework repository and skeleton `.gitignore`. It confirms source-controlled exclusion policy only; it does not inspect untracked values, deployment permissions, secret-manager behavior, or whether an example file contains safe placeholders.

The current migration guard retains the original ADR 027 authority plus ADR 029's forward seventh step. It checks the 23-statement source ceiling, all seven explicit identifiers, unrolled history checks and transaction calls, the `account_users` SQL/checksum source, the real-console evidence, and continued exclusion from framework core and package inventory. It does not validate a deployed schema, infer historical user ownership, or authorize a backfill.

The CRUD profile guard checks only that the installed authority and context route remain available. It deliberately does not inspect consumer directory names: an application may record one canonical alternative structure while remaining subject to the hard consumer contract and Strict Profile.

The typed-input guard retains ADR 021, the operation-specific Create seam and adversarial evidence, the installed type guidance, and the template and skeleton context fields. It does not inspect arbitrary consumer field semantics or add a validator diagnostic; PHPStan proves native boundary types and any typed seam while application tests own representations, effective bounds, generic disclosure-safe failures, parser-versus-policy order, and exclusion from operation-owned downstream work.

The finite-data-path guard retains ADR 022 and the example-owned document collection proof. It checks stable artifacts and source markers for the complete SQLite statements, explicit named parameters, order and cursor grammar, omitted/parsed-empty/one-to-three-category behavior, protected tenant and membership bindings, one-statement non-empty pages, zero-statement empty-selection behavior, and proof limits. It does not parse arbitrary SQL or turn the example into a consumer mechanism. PHT006, tenant predicates, and adversarial binding tests remain complementary path evidence rather than universal authorization or injection certification, and the three-driver harness remains PDO transport evidence only.

The durable-job guard retains ADR 024 and one application-owned SQLite example path. It checks stable documentation, skeleton and template context routes, explicit producer and worker source markers, one-shot command output, required crash and transition tests, continued absence from framework core and package runtime APIs, and the absence of a new `.ai/jobs.md` rejection in the Contract-v6 application checker. It does not certify arbitrary consumer job semantics, parse the SQLite state machine, create a generic queue diagnostic, or prove production filesystem, concurrency, supervisor, retention, replay, or external-effect guarantees. Query budgets, lease-fencing tests, redaction probes, the clean package inventory, and human review remain complementary evidence.

The file-transfer guard retains ADR 026 and one application-owned local-document proof. It checks the POST-only one-normalized-file multipart shape, the raw-scalar-duplicate proof limit, separate total-request and operation file limits, untrusted and discarded client metadata, PHP-temporary-file provenance, explicit move ownership, private generated storage, concrete `LocalFileBody`, exact `Content-Length`, prior-output rejection, fixed-size reads, full-`200` range behavior, real-SAPI requests, and download-to-file evidence. It does not add a generic storage API, trust MIME or filenames, automate persistence or cleanup, certify deployment buffering, claim raw duplicate rejection, or claim support for fields, multiple files, resumable input, images, remote storage, or ranges.

PHPStan runs separately at maximum level with strict rules. It owns static type correctness; `PHT005` resolves literal, imported, aliased, fully qualified, and typed dynamic PDO construction so the framework connection remains the sole boundary. `PHT006` resolves the native SQL-expression type at direct `Connection` database calls and rejects non-finite, blank, annotation-only, unpacked, or indirectly invoked SQL. The consumer checker's structural `EnvironmentAccessProfile` owns PHT007 because one-file confinement needs the complete application manifest. It checks exact access forms, not secret-looking values, arbitrary secret managers, redaction, parsing, deployment safety, or least privilege.

The consumer checker also performs one narrow application-context consistency check without adding a `PHT` diagnostic: application-owned canonical `PHPThis\Database\Connection::connect` calls cannot coexist with a standalone `NOT_APPLICABLE(DATABASE)` declaration in `.ai/data.md`. Token-aware controls cover ordinary, aliased, grouped, namespace-qualified, current-namespace, and fully qualified calls, the exact legacy starter declaration, balanced CRLF marker formatting, unmatched-backtick and quoted-legacy non-declarations, and comment, string, or `Connection::class` non-matches. An explicitly structural synthetic SQLite context passes without a live authority probe. This structural check does not inspect a live database, resolve effective authority or namespace control, prove intended statements are authorized, or establish migration, deployment, verification, and traffic-enablement order.

`php tools/test-strict-profile.php` exercises passing and failing fixtures against the same syntax guard and PHPStan extension used by the canonical check. PHPThis-owned rule IDs are permanent and have no suppression mechanism.

`php tools/test-database-drivers.php` defaults to a temporary SQLite database and fails when any explicitly requested driver or connection configuration is unavailable. The dedicated CI job requests SQLite, MySQL, and PostgreSQL against real services. Its deliberately narrow common SQL proves PDO transport behavior without creating a runtime dialect abstraction; application SQL remains engine-specific. Its PHT006-compatible fixed table names are created and dropped, so non-SQLite runs require a disposable or dedicated test database and intentionally DDL-capable fixture credentials.

Consuming applications use `vendor/bin/phpthis check`. It discovers PHP across the application rather than accepting a fixed list of conventional source roots, rejects symlinked checked source, and passes one captured manifest to syntax guardrails, PHT007, the report-only duplication scanner, and a temporary framework-owned PHPStan configuration. The duplication stage uses a 48-normalized-token minimum and fixed source, token, window, comparison, group, location, path, and output caps; possible, incomplete, and unavailable results remain advisory and cannot change validity. Normal runs use a persistent profile-owned cache and parallelize when the host allows PHPStan's loopback coordinator; restricted hosts fall back to serial analysis. `PHT004` rejects consumer PHPStan configuration, baselines, and inline PHPStan ignores before analysis. Contract version 10 carries forward version 3's structural rejection of `$_SESSION`, direct or imported native session calls, and literal indirect references in every application file, including the front controller; dynamically obscured calls remain forbidden by contract rather than becoming an accepted escape hatch. UUID/ULID routing and route-local request-handler decorators create no additional `PHT` diagnostic; Strict Profile version 3 adds only PHT007.

`php tools/test-application-duplication.php` directly locks the advisory threshold and fixed bounds, no-match behavior, comment and whitespace normalization, maximal overlap consolidation, multi-location and same-file grouping, deterministic order, group and location truncation, incomplete scans, escaped bounded paths, and PHP source-token-content non-disclosure.

`php tools/test-consumer-project.php` builds the real framework release archive, compares every entry with `tools/package-files.txt`, installs that archive into a fresh temporary copy of `skeleton/`, and runs both the installed profile and application behavior stages. Composer and Git export-exclusion policies must be identical; a clean Git checkout also archives `HEAD` and compares that complete inventory. Its controls cover unconventional and extensionless source paths, unsupported PHP suffixes, obscured magic methods, PHT001, PHT002, PHT004, PHT005 construction forms, PHT007 canonical and alternate environment access plus one-file confinement, Contract version 10 carrying the version-3 direct/imported/literal-indirect native-session restrictions, dependency exclusion, configuration and source symlinks, Composer-gate drift, persistent normal-mode caching, explicit debug output, and the pre-alpha-to-tagged skeleton repository boundary. It also verifies that the local skeleton and installed framework distribute ADR 037's database setup guidance. This distribution proof does not establish that an AI asks the scope question, avoids external database I/O, or meets a duration target; the frozen-prompt consumer trial remains separate behavioral evidence. Installed application behavior additionally proves typed runtime/migration configuration separation and the documented bounded request-handler decorator contract without adding framework configuration or middleware mechanisms. The installed skeleton includes an optional WebSocket context route, but the consumer checker deliberately does not require that file and this repository's separate WebSocket proof remains outside the framework package and installed-consumer harness. The harness also plants comment- and whitespace-varied copies in unconventional application locations plus dependency, installed-framework, and VCS controls; the installed normal and debug commands must keep PHP source-token content private and every detail bounded, structural and PHPStan failures non-zero, and deliberate duplication successful through the canonical application behavior stage. Inventory failure prevents maintainer dependencies, cache data, examples, or harness files from silently entering the consumer package.

A separate installed distribution proof checks that ADR 038's application-owned authority lifecycle remains present across the Consumer Contract, database, security, migration, application-context, template, and resolved skeleton guidance. It pins database and object definition source; database, catalog, schema, or attachment namespace selection and qualification as supported by the chosen engine; a namespace and object control or ownership model with explicit non-applicability where unsupported; exact per-operation runtime authority; effective-authority resolution using only applicable engine sources; isolated elevated authority when adopted; one activation and deactivation owner and non-HTTP path, with `GRANT` and `REVOKE` only where supported and selected; pre-traffic verification; and application-owned release sequencing. This marker proof is a source-distribution check only: it performs no live authority probe, validates no engine privilege or control model, and does not prove that any recorded release order was executed.

That local proof establishes the source-controlled Composer and Git export policies; it does not claim that an uncreated hosting-provider archive is identical. The alpha release gate in `RELEASING.md` must install the actual Packagist-preferred dist artifact, compare its complete framework inventory with `tools/package-files.txt`, and run the public skeleton creation command before the release is announced.

`php tools/test-query-scaling.php` verifies that the accepted read remains constant at one query and explicitly submits its `.php.fixture` N+1 negative control to `PHT003`. The fixture is not accepted repository PHP; proving its rejection is part of the test.

The loop check is deliberately syntax-aware. It matches the canonical database method names case-insensitively in loop headers, braced bodies, direct and compound unbraced statements, PHP alternative syntax, and closures declared inside a loop. It does not perform call-graph analysis or resolve dynamically named method calls, so review still has to reject recursive and indirect I/O. PHT006 narrows direct SQL construction but does not prove authorization, stored-procedure behavior, database grants, migration-credential isolation, or universal injection safety. Guardrails should remain deterministic, fast, and locally runnable.
