# CLI composition

Under current Consumer Contract version 14 and Strict Profile version 3, `.ai/configuration.md` is the application authority for process-specific configuration sources, final readonly types, profile, input-name, and credential separation, injection sites, rotation, failure, redaction, and tests. HTTP and CLI share only immutable application configuration and visible construction code. Every permissible shared value is explicitly recorded there. Every HTTP request and console process receives fresh connections, budgets, traces, correlation or clock state, and operation objects appropriate to that boundary. Request, session, and other mutable invocation state never cross entrypoints.

The accepted example's `.ai/configuration.md` records its code-owned and command-line input sources and the limit that its local SQLite proof has no credential or database-grant evidence. `ApplicationComposition` retains only already validated immutable values; it does not read deployment input. `http()` creates the complete fresh HTTP graph, including cache-scoped Redis state only for the protected cache path. The CLI composition returns one explicit `ApplicationCommands` boundary, which creates fresh Redis lease and job-scoped state only when a due command reaches the one-job operation and fresh migration-scoped state only when `database:migrate` runs. No migration state is constructed or executed from HTTP startup, and no Redis object is shared between request and command processes.

The composition object is not injected into behavior and is not a container, service locator, registry, generic factory, framework extension point, or global. Submitted command text is matched only against the finite application-owned command enum.

An adopted local environment launcher is application-owned PHP outside the private child's composition. The launcher and child share the canonical `ApplicationEnvironment` PHP file that owns every direct process-environment read. The launcher resolves the absolute project root, absolute `PHP_BINARY`, and private child; selects one finite command/profile/child mapping; parses local bytes when required; and uses array-form shell-free `proc_open` with an explicit environment containing only the selected application profile and inherited `STDIN`, `STDOUT`, and `STDERR` descriptor resources. It places no secret in arguments and hands off to the same sole console and command spelling without launcher-side stream interception. It neither constructs business dependencies nor introduces another command handler, automatic bootstrap loader, mutable configuration object, or shared process state. [Application-owned local environment launcher](../configuration/local-environment-launcher.md) owns the declarative file and precedence boundary.
