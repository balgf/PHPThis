# CLI testing

For production adoption, execute the real application console in fresh subprocesses. Add evidence for every accepted command and applicable outcome, the complete argument grammar and byte limits, rejection before application I/O, exact exit codes, exclusive stdout/stderr bytes, stable key order, final newline, missing-resource and deliberately injected unexpected-failure behavior, and complete secrets redaction.

When an application adopts the optional local environment launcher, execute the real PHP file separately in fresh subprocesses through the exact `php ./bin/application <command>` forms and its absolute path from outside the project working directory. Prove its shared canonical `ApplicationEnvironment` source; exact finite launcher-command to selected-profile, private-child, and unchanged application-command map; absolute root, `PHP_BINARY`, and child resolution; unknown and invalid rejection before file access; complete inherited-profile precedence; complete file-profile selection only when the selected inherited profile is wholly absent; partial and empty rejection without merging; exact selected child environment; unrelated and elevated profile exclusion; array-form shell-free `proc_open` with inherited `STDIN`, `STDOUT`, and `STDERR` descriptor resources and no launcher-side stream interception; fixed launcher-owned failure bytes; unchanged child-console exit and streams after handoff; no secret in arguments; and complete redaction. Use adversarial ignored files to prove byte-precise parsing, every recorded file, line, key, and value bound, duplicate and unknown rejection, LF and CRLF policy, opaque semicolon and shell-metacharacter preservation, and absence of command, `exit`, substitution, backtick, expansion, redirection, or `PATH` side effects. Clean every file and sentinel in `finally`. See [Application-owned local environment launcher](../configuration/local-environment-launcher.md) for the complete checked boundary.

When a scheduled pass is adopted, use its explicit deterministic clock to exercise the recorded time boundaries and prove not-due performs no scheduled operation. When that pass adopts ADR 028's Redis lease, additionally prove a held lease produces immediate `overlap_skipped`, injected connection, acquisition, renewal, and release failures are generic and fail-closed, and owned release occurs after success and failure. Assert the exact bounded `coordination` list on every applicable schedule success and Redis operational failure while preserving one-line stream exclusivity and redaction.

For the accepted scheduled-pass shape, prove one due pass calls the same one-job operation at most once and handles at most one delivery. Record and test its catch-up, slot-ledger or no-ledger, and repeated-in-slot policy; the current example has no catch-up or slot ledger and does not deduplicate sequential invocations in one due minute. Every adopted console verifies fresh HTTP and CLI mutable state under only the recorded immutable shared configuration.

For an adopted migration command, prove the exact recorded initial baseline and manifest order, finite exact-engine ledger-metadata acceptance and incompatible or additional-unrecorded-object rejection before history or pending work, exact bounded ledger state, unchanged no-op rerun, statement and code-owned binding or finite binding-policy drift, malformed or overflowing ledger rejection before pending work, same- and cross-topology exclusion or authority gating, the stable coordination namespace and protected interval, every applicable transaction, implicit-commit, non-atomic, and crash-visible state across checksum-covered DDL, data, and authority effects, cross-history recovery when histories interact, immutable committed history, forward continuation, and complete output redaction. Exercise application- or database-owned coordination through concurrent real commands, including prior-owner fencing or confirmed termination when coordination can expire or be lost. Exercise deployment or external serialization at its owning boundary around the complete command and prove a bypassing invocation cannot obtain migration configuration or authority. Prove ordinary HTTP startup performs no migration work. For the ADR 027 SQLite proof, additionally prove its empty-database case, immediate same-host `flock` contention with no database change, and per-migration rollback with earlier commits preserved; do not generalize those results to another engine or topology.

When a scheduled pass adopts the ADR 028 lease, also prove `SET NX PX` owner-token acquisition, explicit renewal, stale-owner renewal and release rejection, safe owned release, separate `noeviction` topology, backend outage, process termination, and post-expiry acquisition against the recorded Redis version. The current real-backend evidence renews TTL, rejects a stale owner after a successor acquires, and distinguishes server rejection from contention on the lease process. The focused proof does not establish fencing, failover, replication, restart, partition, pause, clock, or exactly-once behavior.

These are consumer evidence requirements. The current example proof is intentionally bounded: its real-console cases cover invalid, unknown, missing-database, `completed`, and `idle`; direct command and Redis integration tests cover deterministic cadence and coordination; ADR 024 worker tests plus exhaustive typed mapping and static analysis cover retry and dead-letter outcomes. The focused console proof does not replace the complete application gate.
