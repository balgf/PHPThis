# File-transfer testing

Test the boundary and operation separately, then execute the real HTTP path.

Boundary evidence covers multipart disabled, POST-only, boundary missing/empty/duplicate/oversized and disallowed unquoted characters, canonical and overflowing `Content-Length`, total cap, transfer encoding, text fields, empty upload map, every upload error, unknown error, nested and multiple normalized shapes, missing/unknown/wrongly typed keys, controls, temporary-path bound, contradictory metadata, reported size, ordinary-body compatibility, and route-copy preservation.

Pre-PHP evidence executes the deployed or representative web-SAPI path and records dated effective proxy, web-server, and PHP values, including `file_uploads`, `upload_max_filesize`, `post_max_size`, `max_file_uploads`, `max_multipart_body_parts`, and `upload_tmp_dir`. Exercise exact-limit and maximum-plus-one requests at the owner expected to reject them. `max_multipart_body_parts` proves only a total raw-part bound; separately prove the operation's decision that PHP-normalized duplicate scalar parts are suitable, or exercise the selected upstream duplicate-name rejection. Do not infer either outcome from `count($_FILES)`.

Application evidence covers exact field ownership, inclusive minimum and maximum bytes plus zero-byte policy, exact-limit and overflow behavior, rejection before storage, `is_uploaded_file`, hostile filename/media/path non-use, generated identifier grammar, private root and retained modes, successful move ownership, one test-only fixture hash comparison, missing file, and public/terminal redaction. The example retains no integrity digest, accepts 0 through 1,048,576 bytes inclusive, and intentionally has public routes, so it proves no authorization policy. It does not inject an actual-size race or kernel move/chmod/cleanup failure; an adopter must add applicable fault proofs and, when it makes an integrity claim, digest-lifecycle proofs before stronger operational claims.

Protected application evidence proves exact `authenticate -> resolve tenant when applicable -> authorize upload -> validate CSRF when applicable -> rate/concurrency admission -> atomic quota reservation -> storage` order; unauthenticated, forbidden, cross-tenant, permitted, and unexpected-policy-failure outcomes; no later step after denial; and authorization-before-lookup for confidential downloads. Assert retained metadata and storage identity remain bound to the applicable tenant, owner/principal, and named action; record each inapplicable dimension instead of inheriting protection from the framework or opaque identifiers.

Filesystem evidence separately proves the dedicated effective web-SAPI `upload_tmp_dir` and deployment-precreated durable root. Assert exact owner/group, ACL or explicit none, modes, no-execute/non-public mount, regular/non-symlink behavior, least non-root request authority, capacity/inode monitoring and alert owner, stale cleanup, lifecycle, and topology. Prove HTTP handling does not create or repair the durable root and its identity cannot and need not create, chmod, chown, repair, or replace it. Prove the PHP temporary path never enters persistent data, a job, log, trace, or later request and that durable work receives only the post-move destination/reference. Quota evidence covers each adopted byte, count, rate, principal, tenant, object, deployment, egress, or aggregate boundary plus concurrent reservation, release, rollback, owner outage, and cleanup-accounting behavior. Lifecycle evidence injects move failure, response failure and ambiguous client retry, process crash at each ownership transition, disk full, inode exhaustion, permission failure, and partial cleanup, then proves retry/idempotency, reconciliation, retention, deletion, replica/backup propagation, restore, legal hold, and bounded supervised recovery as applicable.

Content evidence names exactly `OPAQUE_BYTES` or `INSPECTED_CONTENT`. Opaque evidence proves fixed code-owned stored/download names, no parser or active-content response, exact `application/octet-stream` attachment plus `nosniff`, cache and authentication/authorization policy, and the explicit absence of a content-safety claim. Inspected evidence runs the selected versioned definition and pinned classifiers, parsers, or scanners against accepted, rejected, malformed, oversized, nested, compressed, timeout, resource-exhaustion, quarantine, update, and outage paths within the recorded bounds. Pending, scanner-error, rejected, and quarantined fixtures remain non-serving until an accepted promotion. Change every recorded definition input—tool/version, configuration, signatures, accepted-format allowlist, and application policy—and prove whether retained bytes enter the bounded reinspection selection or remain labeled under the earlier definition. Reinspection evidence covers deterministic order, maximum batch and rate, retry, concurrent update, non-serving state, newly accepted/rejected transitions, accepted promotion, completion, interruption, resume, and failure recovery without silently treating old results as current. Neither posture trusts the client filename, extension, path, or media type.

Response evidence covers absolute path and byte invariants, empty ordinary body, exact `Content-Length`, duplicate and control-bearing headers, prohibited transfer/range framing, prior-output rejection, opened-target regular-file and changed-size checks before headers, exact byte output, fixed chunking, handle closure, path-free errors, pre-header fallback, and the response-started no-replacement policy. It pins the exact emitter guarantee: one pre-header regular-file and length check followed by one sequential pass that emits the declared count or throws, never intentionally emits more, and never retries or replaces a started response. The repository proof deliberately shows that an equal-size regular replacement and a symlink to a same-size regular target are emitted. For the current path-only profile, prove the mandatory application/deployment invariant that the selected pathname and bytes remain immutable under exclusive-writer authority from authorized selection through completed emission. A digest test is additional evidence, never a substitute for that invariant; it names its algorithm and covers match, mismatch, replacement, lifecycle transition, deletion, backup/restore, and reinspection interaction. Evidence based on an identity-bound body, open handle, or different response primitive belongs to a separately accepted core/response decision. The emitter proof does not establish path or inode identity, immutable content, integrity, client receipt, network completion, or external buffering.

The repository real-SAPI proof starts PHP's built-in server with explicit upload settings and displayed errors enabled, uses `curl --form`, writes downloads to files, verifies hashes, modes, headers, and redaction, tests exact-limit/oversized/missing/normalized-multiple/duplicate-scalar/hostile metadata, and proves a range request receives the full `200`. The scalar-duplicate case records PHP's pre-boundary collapse rather than claiming rejection. Its public non-production routes prove no authentication, tenant, authorization, CSRF, quota, scanner, retention, production ingress, or multi-host policy. The fixed 8,192-byte loop is application-level memory evidence; record separately whether deployed PHP, server, proxy, and client buffering were measured.

Static installed-context proof may require the authoritative application adoption record and its finite markers, routing, and complete project-gate link. It cannot prove effective SAPI settings, filesystem authority, request policy, quota concurrency, content inspection, lifecycle, or delivery. Those remain application-owned behavior, integration, and deployment evidence against the selected mechanisms.
