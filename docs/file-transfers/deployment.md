# File-transfer deployment

Application limits must align with the complete ingress path. Record and verify at least:

- PHP `file_uploads`, `upload_max_filesize`, `post_max_size`, `max_file_uploads`, `max_multipart_body_parts`, `upload_tmp_dir`, and request input and execution limits, with the dated effective web-SAPI values rather than only a source configuration file;
- web-server and reverse-proxy connection, header and request bytes, method and media-type filtering, buffering, timeout, request rate and concurrency, temporary storage, first rejecting layer, and externally observable rejection response or connection behavior;
- dedicated effective web-SAPI `upload_tmp_dir` with named non-root request identity, owner/group, exact ACL or explicit none, permissions, non-executable/non-public mount, capacity/inode monitoring, request/stale cleanup and topology for every profile;
- the selected durable-storage deployment: `LOCAL_ADR026` adds its deployment-precreated durable root before HTTP handling, request-identity authority exclusion, exact owner/group/ACL-or-none, permissions, local-versus-network/mount semantics, unrelated-writer exclusion, capacity/inode monitoring, backups, recovery, container lifecycle and multi-host visibility; `AMAZON_S3_ADR053` instead records every exact account/bucket/KMS/IAM/versioning/lifecycle/network/runtime/deployment fact in [Amazon S3](amazon-s3.md) and marks the local durable root not applicable;
- selected response buffering or offload behavior, timeouts, client disconnect behavior, TLS termination, and maximum supported file size; and
- authentication, tenant resolution, authorization, CSRF when cookie-authenticated mutation applies, quotas and concurrent reservation, opaque or inspected-content policy, retention, deletion, audit, privacy, and incident response.

`max_multipart_body_parts` limits total raw multipart resource use; it does not prove that PHP rejected duplicate raw scalar names before normalizing them. An operation that cannot tolerate that ambiguity needs a tested upstream duplicate-name rule or a separately accepted raw parser. Record whether the limitation is suitable rather than treating a PHP setting or `count($_FILES)` as duplicate evidence.

The example transport cap is 2 MiB and its per-file/aggregate file caps are 1 MiB; the operation accepts 0 through 1,048,576 bytes inclusive. Its fixture explicitly disables automatic POST parsing and enables uploads. The native call pins count limits to 32 fields, 8 files and 40 parts. Separate real-SAPI tests deliberately set lower global automatic-parser limits and verify that the explicit native options own the parse. These are local non-production facts, not production deployment certification. See the [Nginx/FPM replay](https://github.com/balgf/PHPThis/tree/main/tools/runtime-proof/issue-104) for buffered HTTP truncation evidence.

Automatic POST parsing must be disabled for enabled multipart. `RequestReader` passes explicit request/file/count/part limits to `request_parse_body()` and rejects native parsing exceptions; it never falls back to `$_POST`/`$_FILES`. Record effective `enable_post_data_reading`, `max_input_vars`, the explicit options, `max_input_nesting_level`, input filters, encoding translation and upload-progress extensions alongside the settings above. The supported reference disables upload progress and encoding translation and uses the unmodified input filter. Verify no earlier body reader and test startup/restart settings in the actual SAPI. Ordinary JSON and URL-encoded bodies continue through the ordinary-body path. PHP may still ignore malformed parts or accept a missing closing boundary; operations requiring strict raw-body validity need separately verified upstream validation.

Quota and lifecycle policy names every dimension actually enforced: request, file, principal, tenant, resource, deployment, egress, count, rate, aggregate bytes, and the selected storage's capacity/cost/resource limits. Record how concurrent writers atomically reserve and release capacity, whether failure is fail-closed, and the generic public outcome. Record retry, idempotency, duplicate-request, and ambiguous client-response behavior. `LOCAL_ADR026` names deterministic handling and recovery for move failure, response/emission failure, process crash, disk full, inode exhaustion, permission failure, and partial cleanup. `AMAZON_S3_ADR053` uses the exact finite cross-system failure, reconciliation, quota-retention, deletion and incident table in [Amazon S3](amazon-s3.md). Every profile names one bounded reconciliation path for abandoned reservations, orphans, partial writes and failed cleanup; the owner and schedule for temporary and expired-object deletion; deletion propagation into replicas and backups; restore interaction; legal hold; and incident response. PHPThis performs none of this automatically.

References: [PHP file-upload configuration](https://www.php.net/manual/en/ini.core.php#ini.file-uploads), [PHP POST upload behavior](https://www.php.net/manual/en/features.file-upload.post-method.php).
