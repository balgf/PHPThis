# Checked PCM WAV inspection recipe

Use this optional `LOCAL_ADR026` / `INSPECTED_CONTENT` recipe for short catalog voice clips deliberately exported as mono 16 kHz, 16-bit PCM. The [catalog reference](https://github.com/balgf/PHPThis/tree/main/tools/inspected-media) shares private quarantine, owner binding, quotas and recovery with its [PNG](inspected-png.md), [JPEG](inspected-jpeg.md) and [MP4](inspected-mp4.md) operations. Its `.ai/file-transfers.md` owns the complete application policy. Consumer Contract 26, Strict Profile 4, framework runtime, Composer dependencies and starter remain unchanged.

## Exact accepted representation

`CATALOG_WAV_PCM16_MONO_16KHZ_V1` accepts 46–320,044 actual file bytes, with a positive duration through ten seconds. The format is little-endian RIFF/WAVE, one 16-byte `fmt ` chunk followed by one terminal `data` chunk. Require PCM format tag 1, one channel, 16,000 samples/second, 16 bits/sample, 2-byte block alignment and 32,000 bytes/second. The data has 1–160,000 complete signed sample frames (2–320,000 bytes). Both length claims must match the actual bytes exactly.

The [RIFF chunk model](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-) allows broader layouts; this operation deliberately accepts only that fixed two-chunk representation. Extra/duplicate/reordered chunks, metadata (`LIST`, `bext`, `fact`, `JUNK`), padding, trailing bytes, RIFX/RF64/BW64/Wave64, extensible/float/compressed encodings, other channel counts, rates and depths are rejected. A valid WAV outside this profile needs deliberate preparation by the application, not automatic conversion during upload.

`BoundedWav` performs structural inspection. It derives expected lengths from the already bounded input, compares the complete fixed header and checks data alignment. For [signed 16-bit PCM](https://learn.microsoft.com/en-us/windows/win32/multimedia/devices-and-data-types), every sample bit pattern is valid; there is no compressed stream or expansion stage requiring a codec. The validator does not allocate a sample array or spawn a decoder. This establishes representation and sample-resource bounds, not sound quality, intelligibility, malware absence, hidden-information removal or playback safety.

## Upload, inspection and delivery

`POST /catalog-audio-clips` requires exactly one `clip`, no scalar fields or query parameters. The existing 2 MiB native multipart ceiling remains. Authentication and named authorization precede protected work; admission verifies provenance, actual/reported size equality and the tighter 46–320,044-byte WAV bound before quota reservation. Client filenames and MIME labels never choose inspection. The legacy `image_id` response key and internal catalog names remain compatible.

The existing isolated PHP 8.4.26 worker adds this parser without another binary or dependency. It keeps the fresh read-only container, no mounts/network, UID/GID 65534, dropped capabilities, no-new-privileges, eight PIDs, 64 MiB memory/swap, 32 MiB PHP memory, one CPU, two CPU seconds per process, ten-second supervisor deadline and 8 KiB output caps. Cleanup calls have separate three-second bounds; an external supervisor bounds the complete maintenance command. Structural failures are `rejected`; unavailable processes, timeout, unexpected output or unresolved cleanup are `scanner_error`. Both remain non-serving. Promotion requires the recorded inspection, digest checks and verified container absence.

All four formats share 32 objects/32 MiB, 24-hour eligibility, one inspection start/second, two attempts per object/definition, explicit retry/reconciliation and exact deletion. Rejected/error reservations count toward quota. Definition changes make old acceptance ineligible until reinspection, including retained WAV clips.

`GET /catalog-audio-clips/{image_id:token}` binds trusted owner, WAV format, current definition and expiry. Missing, other-owner, wrong-format or ineligible records share a private 404. Success returns original bytes as the [registered PCM type](https://datatracker.ietf.org/doc/html/rfc2361#appendix-A.2) `audio/vnd.wave; codec=1`, fixed `attachment; filename="catalog-clip.wav"`, exact length, private/no-store, nosniff and `Accept-Ranges: none`. Range requests receive full 200. Playback, streaming, transcoding, resampling, transcription and external processing are separate capabilities.

## Retained catalog migration

Drain HTTP and workers before widening the SQLite format CHECK to `png/jpeg/mp4/wav`. [`tests/wav-migration.php`](https://github.com/balgf/PHPThis/blob/main/tools/inspected-media/tests/wav-migration.php) contains separate constant statements for two exact pre-WAV baselines: the documented MP4 upgrade with `DEFAULT 'png'`, and the fresh MP4 fixture without a default. Each rebuild explicitly copies all eleven columns, preserves values and other constraints, and retains its original default policy. A transaction is required; unfamiliar definitions or unreviewed table indexes/triggers fail before mutation. Tests roll back after every stage and reject blind reruns.

This is a transition proof. The adopter still owns its [migration history](../migrations.md), exact database/version, dependent objects, coordination, ledger, authority and deployment. The reference never runs migrations in HTTP or Composer. Deploy coherent schema/code/policy/image, activate a new definition and reinspect retained PNG/JPEG/MP4 content before serving; availability pauses during reinspection. Keep existing `PHPTHIS_PNG_*` configuration names. Rollback preserves WAV identity, ownership and quota until resolved and uses a new reviewed definition, never relabeling audio or restoring retired acceptance.

## Verification and adoption

Run `composer test:inspected-media`, the reference README's Docker builds and `python3 tools/inspected-media/run.py`, then `composer check`. Synthetic fixtures are generated locally without host audio tools or user recordings. Offline cases cover sample/length/format boundaries, migration rollback and all four catalog lifecycles. Real-container cases repeat resource failures and cleanup; native HTTP tests use Python's independent WAV writer/reader for the maximum-sized clip and exercise admission, owner/format isolation, quarantine, reinspection, outages/retries, expiry and shared quotas. Dated source/tool/image identities are retained in `evidence.json`; CI repeats the real proof.

Production adoption completes the existing [deployment](deployment.md), [storage ownership](storage-ownership.md) and [testing](testing.md) requirements, including real authentication, applicable CSRF, ingress controls, private volumes, distinct HTTP/worker authority and supervised recovery. This local reference supplies no S3 audio inspection or production deployment evidence.
