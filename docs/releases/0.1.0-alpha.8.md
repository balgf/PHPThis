# PHPThis 0.1.0-alpha.8

Source-preparation status: accepted on 2026-09-27 (Asia/Manila)

These are accepted source-preparation release and upgrade notes for [ADR 062](../decisions/062-bounded-alpha-8-release-scope.md). Alpha 7 remains the latest published coordinated release. [Issue #81](https://github.com/balgf/PHPThis/issues/81) records the exact candidate approvals, planned date and eventual artifact evidence; all are pending during preparation. These notes establish no published Alpha 8 artifact.

Selected Composer version: `0.1.0-alpha.8`. Selected framework and skeleton tag names: `v0.1.0-alpha.8`. PHP remains `~8.4.0`; the framework retains zero third-party runtime dependencies and a 2,618-line core under the 2,620-line ceiling. Alpha 8 remains experimental, with no production-readiness or cross-prerelease compatibility guarantee.

## What changes from Alpha 7

The release rolls up accepted hardening and authoring work: Consumer Contract **13 → 18**, Strict Profile **3 → 4**, and diagnostics **PHT001–PHT008**. Public runtime signatures remain unchanged, but newly rejected values, source layouts and emission states make this an intentional prerelease compatibility change. Updating the dependency alone does not migrate application-owned entrypoints or context.

| Change | Upgrade impact |
| --- | --- |
| Value-free Composer configuration (ADR 055) | Keep application configuration values and environment mutations out of Composer scripts. The checker correlates script text with the application’s declared environment keys; value-free entrypoints preserve explicit process delivery and typed parsing. |
| Request-target/path bounds (Contract 14) | Raw bytes `0x00`–`0x20` and `0x7F` are rejected in the entire request target, including its query suffix, and in direct Request/Route paths. Existing limits remain; PHPThis does not decode, normalize or repair rejected paths. |
| Distinct named placeholders (Contract 15 / Profile 4) | PHT008 requires a distinct exact name for every named placeholder occurrence in each accepted finite SQL alternative. Bind repeated values separately under different names. This is not a SQL parser or a binding-array correctness proof. |
| Source inspection (Contract 16) | The checker rejects application symlinks outside dependency/VCS exclusions, unsupported executable suffixes and noncanonical extensionless launchers. Non-PHP files must be readable; ambiguous prefixes fail conservatively at the documented 4,096-byte boundary plus one-byte lookahead. |
| Pending output (Contract 17) | ResponseEmitter rejects emission when headers were sent or any active PHP output buffer holds bytes. Empty buffers remain valid. Preserve prior bytes and buffer ownership; do not discard them to bypass the check. |
| Outer HTTP failures (Contract 18) | Applications establish a generic-first outer boundary around configuration/bootstrap/composition/coordinator work after autoloading and generic-response construction. Response emission retains its separate failure boundary. Production and staging remain generic; optional development details require the exact bounded disclosure profile. |

Connection now constructs PDO through native `PDO::connect` behind its existing boundary. The release makes no SQL/DDL portability claim: use explicit engine-specific SQL and verify each adopted engine/version. See the [contract upgrade companion](../consumer-contract-upgrades.md), [Strict Profile](../strict-profile.md), [configuration](../configuration.md), and [error guidance](../errors.md) for the authoritative details.

## Upgrade from Alpha 7

1. Inventory application-owned source, Composer scripts, direct Request/Route construction, SQL and bindings, response emitters, HTTP entrypoints and deployment settings. Review Contract 14 through 18 and Profile 4 before changing the lockfile.
2. Move configuration values out of Composer scripts. Repair newly rejected path fixtures and source layouts at their owner. Keep literal `.php` files or the exact permitted extensionless prefix; replace application symlinks rather than adding ignores.
3. Give every repeated SQL placeholder occurrence its own name and explicit binding, even when values are equal. Keep finite visible SQL and verify changed statements against each recorded engine/version, including query budgets and traces.
4. Remove unintended early output at its source. Test pending bytes in top-level and lower-level buffers and unchanged empty-buffer behavior. Preserve the rule that `ResponseEmissionFailed(true)` receives no fallback response.
5. Adapt the deployed front controller and bootstrap together, using the current skeleton as a structural reference without overwriting application policy. Autoload first, construct the generic failure response, catch application configuration/bootstrap/coordinator failures, emit only the bounded redacted outer event, and retain separate response emission. Keep deliberate code-owned `GENERIC` unless the optional disclosure profile is explicitly adopted.
6. Verify the real web SAPI: all `E_ALL` bits reported, native display/startup display off, private error logging on, and `zend.exception_ignore_args=On`. Add process/SAPI regression cases for bootstrap/configuration failure, redaction and event-sink failure. Preserve normal request summaries and application success/denial behavior.
7. Reconcile project-owned context through the installed knowledge map and concern routes. Preserve product decisions and adopted profiles. Operation coordination and RAG remain optional; upgrading adds no model provider, vector service, auth, queue, migration or logging runtime.
8. Once the approved Alpha 8 package exists, select its exact version through normal Packagist resolution, regenerate and review the lock, and run zero-argument `composer check` plus every adopted integration and deployment proof on PHP 8.4.x. Record the actual package/source identities and failed attempts. Do not describe a source or local-archive rehearsal as public-release evidence.

## Guidance and retained evidence

Concern-local routing and the smaller universal contract direct ordinary work to one relevant guide. These documentation changes do not weaken authority or validity checks. Native and selected development-tool attributes remain permitted without becoming a runtime discovery/wiring mechanism.

The [retained account-directory consumer](https://github.com/balgf/PHPThis/tree/main/tools/consumer-lifecycle/issue-71) exercises a feature on public Alpha 7, then an in-place source upgrade to Contract 18/Profile 4 and a fresh qualitative review. Its complete gate and clean replay passed; the source upgrade changed entrypoint/bootstrap behavior without rewriting domain operations. This is synthetic maintainer-led evidence, not independent adoption or a long-term production maintenance result. Repeating it against the eventual public Alpha 8 pair remains pending.

The [LLPhant/Qdrant guide](../rag.md) records an application-owned recipe using deterministic embedding/generation protocol fixtures and real isolated Qdrant. Stock LLPhant Qdrant and the inspected OpenAI-client paths retain incompatible discovery behavior and are excluded. No live model compatibility, retrieval quality, grounding, billing or ANN-performance claim follows. No RAG dependency or service enters the framework or health-only starter.

Maintainer evaluation adapters, measured reading observations, failure/repair evidence and supply-chain controls remain bounded evidence under export-excluded tools. They are not consumer runtime capabilities, generic productivity guarantees, or authorization for another paid campaign.
