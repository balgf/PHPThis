# PHPThis 0.1.0-alpha.9

Source-preparation proposal dated 2026-10-16 (Asia/Manila). The proposed Composer version is `0.1.0-alpha.9`, with `v0.1.0-alpha.9` tags for both framework and skeleton. [Issue #124](https://github.com/balgf/PHPThis/issues/124) owns exact candidate commits, review, approvals and later publication evidence. These notes describe the proposed scope; they do not establish package availability or authorize publication. [RELEASING.md](../../RELEASING.md) owns the ordered release gates.

The proposed boundary is Consumer Contract 22, Strict Profile 4 and diagnostics PHT001–PHT008. PHP 8.4.x, PDO and `ext-session` remain required; the framework has zero third-party runtime dependencies. This is experimental evaluation software with intentional compatibility changes between prereleases and no production-support commitment.

## Changes since Alpha 8

| Contract | Change | Application impact |
| --- | --- | --- |
| 19 | Optional immutable `ErrorRepresentation` for routing 404/405 and coordinator-selected 500 responses | Adopt explicitly; defaults and the independent early-failure fallback remain built in. |
| 20 | Optional server-reported `PeerAddress` on `Request` | Malformed present `REMOTE_ADDR` now fails ingestion; retain the value in request copies. |
| 21 | Explicit native multipart parsing into bounded `MultipartForm` values | Every application changes its HTTP handoff. Multipart adopters also migrate reader configuration, request construction and web-SAPI settings. |
| 22 | Optional generated S3 inventory exports and bounded internal reads | Application-owned recipe and verification only; no additional framework runtime API or default dependency. |

The [contract upgrade history](../consumer-contract-upgrades.md#contract-version-22) retains each change's introduction version and full obligations.

Checked application guidance now includes finite optional filters, sorting and bulk writes in [database patterns](../database.md), [named-header machine authentication](../stateless-authentication.md), [MySQL durable welcome work](../jobs/mysql.md), [inspected PNG quarantine](../file-transfers/inspected-png.md), and [generated S3 exports](../file-transfers/generated-exports.md). These recipes retain explicit wiring, operation-specific authority and bounded I/O; adopting one does not add a framework service.

Maintainer guidance uses one required `AGENTS.md` per audience followed by the relevant task guide. [ADR 063](../decisions/063-maintainability-review-over-size-proxies.md) replaces size/file-ratio gates with concrete maintainability review; [ADR 064](../decisions/064-one-entrypoint-per-audience.md) records the reading policy. Existing applications reconcile their own context deliberately. Contributor setup, package-route checks, dependency audit, MySQL readiness and PNG diagnostics/resource tests have also been strengthened.

## Upgrade from Alpha 8

Read the installed Contract 22 and reconcile project-owned instructions before adopting the new package. A Composer update does not migrate application PHP, configuration or deployment settings. Keep the exact public Alpha 8 installation command until the coordinated Alpha 9 package and clean-install evidence are recorded in #124.

### Required for every application

1. Change the sole front controller to the two-array handoff:

   ```php
   $response = $coordinator->handle($_SERVER, $_GET);
   ```

   Update the terminal coordinator's signature and its calls to `RequestBoundary::handle($server, $query)` and `RequestReader::read($server, $query)`. Remove parsed field/file arguments and earlier reads of those automatically populated arrays, including when multipart is disabled. Do not retain extra arguments: PHT007 accepts only the new canonical handoff.

2. Audit `Request` construction and copying. Its seventh argument is now `?MultipartForm $multipart`, replacing the old uploads array; the optional eighth argument is `?PeerAddress $peerAddress`. Replace named `uploads:` arguments and positional upload arrays. Preserve both `multipart` and `peerAddress` in application-owned copies. Existing `$request->uploads` reads remain supported as the form's upload projection.

3. Verify server peer metadata. A missing `REMOTE_ADDR` yields `null`; a malformed present value throws redacted `InvalidRequest` before body, session or handler work. Correct the actual server/FastCGI source and test missing, valid and malformed values. Forwarding headers supply no fallback, and server-reported metadata alone establishes neither an original client identity nor trusted-proxy policy. See [peer-address guidance](../request-handling.md#server-reported-peer-address).

4. Run the complete application gate on PHP 8.4.x. Cover the new handoff, request copies, ordinary bodies, disabled multipart, registered ingestion failures and session ordering. Preserve Alpha 8's generic-first outer failure boundary, response-emission restrictions and Strict Profile 4 checks.

### Multipart adopters

Replace the third `RequestReader` integer argument, formerly named `maximumMultipartBytes`, with `multipartLimits: new MultipartLimits(maximumRequestBytes: ..., maximumFileBytes: ..., maximumTotalFileBytes: ...)`. Select positive bounds satisfying `maximumFileBytes <= maximumTotalFileBytes <= maximumRequestBytes < PHP_INT_MAX`. The first two reader arguments remain `maximumBodyBytes` and `inputUri`; an omitted or `null` third argument keeps multipart disabled.

For constructed requests and fixtures, use `multipart: MultipartForm::fromPhp($fields, $phpFiles, $declaredBytes, $limits)` with native PHP file metadata, not preconstructed `RequestUpload` objects. Read fields from the non-null `$request->multipart->fields`. Follow the exact name, count, metadata and byte limits in [request ingestion](../file-transfers/request-ingestion.md).

Configure the actual web SAPI with `enable_post_data_reading=Off`, `file_uploads=On`, no earlier body reader and the [deployment controls](../file-transfers/deployment.md). Restart affected PHP processes and test ordinary bodies, single-file and expanded multipart requests through that SAPI. Multipart is POST-only, requires a declared length and rejects transfer encoding; `RequestReader` calls the native parser once.

Accept the parser boundary explicitly: native limit exceptions reject the whole parse, but PHP can normalize or collapse names, discard malformed parts or accept a missing closing boundary. It is not strict validation of the raw multipart syntax. Validate required/unknown fields and every supplied upload before operation I/O. Existing single-file storage operations remain single-file unless their application policy is separately expanded.

### Optional error representations and S3 exports

An error-format adopter constructs immutable `ErrorRepresentation(contentType: ..., body: ...)` values inside protected composition. Content type must be nonblank, free of control bytes and at most 256 bytes; body is at most 65,536 bytes. Inject routing formats through `Application` and the coordinator's unknown-failure format through `UnknownFailureBoundary`. Preserve status, `Allow`, cache, correlation and session behavior, and test defaults, overrides and invalid construction. Keep the unconfigured fallback before bootstrap: clients must still accept its built-in 500 when composition fails. See [error representations](../errors.md#framework-error-representations).

A generated-S3 adopter follows [the adoption boundary](../file-transfers/generated-exports.md#application-adoption-and-deferred-aws-proof): separate generated provenance and CLI authority, bounded memory-only writes/reads, exact object-version ownership, quota and ambiguity reconciliation, and 24-hour retention. Its verifier has separate source, behavior, real-AWS and deployment modules; the existing seven-role upload/redirect proof does not cover this mode. No automatic data migration or AWS dependency is added to non-adopters.

## Evidence and retained limits

The framework gate covers runtime, static analysis, installed consumers and package/export parity. Required CI additionally checks the recorded PDO engines, MySQL durable work, inspected PNG resource bounds, dependency audit and workflow security. Exact candidate results belong in #124; local success does not establish a public package or production behavior.

[Swoole](../performance.md#swoole-experiment) remains an optional stateless experiment; the conventional PHP front controller remains the contract. The [two-start pilot](../evaluation.md#observed-two-start-pilot-96) provides bounded feasibility observations with its guide-reading limitation, not comparative superiority or a general AI-success rate. Further study remains deferred.

Generated S3 has offline reference evidence, including the real SDK against a loopback fixture. Actual AWS/KMS and deployment verification is required when an application adopts it. [Issue #110](https://github.com/balgf/PHPThis/issues/110), external-service consumption of a file URL, remains deferred because the selected scope is storage and downloads only.

Framework-owned authentication, authorization, CSRF policy, queues, migrations and deployment remain outside this release. Applications select and prove their own policies. Earlier tagged release notes and accepted decisions retain their historical scope and introduction versions.
