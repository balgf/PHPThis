# Inventory export policy

`REFERENCE_ONLY(AMAZON_S3_ADR053, GENERATED_INVENTORY_ADR068)` — offline reference; no adopted AWS or production deployment. This is the single writable application storage/lifecycle policy. Contract 22 and `docs/file-transfers/generated-exports.md` own the framework extension.

- Operation: tenant-free, single-host trusted CLI inventory export. HTTP/browser routes, upload fields, PHP temporary uploads, browser authentication and CSRF, tenants, redirects and external consumers are not applicable. The supervisor supplies workload authority; no unauthenticated HTTP adaptation is implied.
- Source: private preprovisioned SQLite `inventory`, at most 1,000 typed rows, one SELECT LIMIT 1001, ordered SKU, integer quantity. Fixed CSV header/columns/LF; 1–65,536 generated opaque bytes. No active parsing or downstream spreadsheet safety guarantee.
- Storage: actual regional Amazon S3 only; SDK 3.392.1, Guzzle 8.0.2, PSR-7 3.1.0 and the committed complete lock. All ADR 053 bucket/KMS/IAM/TLS/audit constraints apply. Their actual resource identities and deployment facts are currently unverified.
- Ownership: random 32-lowercase-hex ID, fixed private-documents/v1 key, never reused. Metadata binds size, SHA-256 and target fingerprint (bucket/region/account/KMS), timestamps, state, exact non-null VersionId and persisted delete-attempt count. Metadata loss is an incident; objects are never adopted from broad listings.
- Admission: reserve metadata before Put. At most 32 live/reserved objects, 2 MiB, 256 total identities. Failed collisions and proved pre-send failures release live quota; ambiguity retains it. Deleted/failed rows remain as ownership tombstones. No history recycling or automatic migration.
- Content: `OPAQUE_BYTES`, fixed application/octet-stream and profile metadata. Put uses conditional create, STANDARD, SSE-KMS with bucket keys disabled and explicit owner/checksum. Exact retained facts are checked at Head and Get, including absent storage/archive/expiry and encoding/range/delete-marker fields.
- State: pending → stored → accepted; failed is only proved no-object/collision. Uncertainty retains pending/stored/reconciliation_required. A collision is never inspected. Empty uncertain-write listing is unresolved. One exact version plus valid Head can reconcile acceptance. Marker/sibling/multiple/truncated/unknown ownership is an incident.
- Expiry: created + 86,400 seconds, checked before and after read. Expiry disables serving independently of cleanup. Persist deletion_pending and attempt count before exact-version Delete. At most two attempts across restarts; verify absence before deleted/release. No fixed physical deletion deadline during outage.
- Concurrency/durability: private precreated 0700 root, 0600 SQLite/lock, current non-root UID, regular non-symlink/non-hardlinked files, unrelated writers excluded. Same-host flock, nonblocking exclusive mutation/shared read through validation. SQLite DELETE journal and FULL synchronous, local durable filesystem; backups/restore/loss recovery require operator review. No multi-host guarantee.
- Bounds: memory-only staging/read sink, 64 KiB data / 16 KiB control responses, PHP 64 MiB; deployment OS memory bound still to be measured. Connect 2s, operation 10s, retries/redirects/decompression off, at most four remote calls and external 60s command deadline. No retry loop, default credential chain or disk payload staging.
- Read errors: missing, permission, timeout, partial bytes, corrupt checksum or retained-fact mismatch return no bytes. Close all handles; no fallback/latest-version read.
- Process authority: writer Put/Head, reader GetVersion, reconciler ListVersions/Head, deletion ListVersions/Head/DeleteVersion. KMS actions and exact resource grants need real AWS verification. No DeleteObject-without-version or bucket/key administration. Distinct inputs and fresh short-lived tuple per process are owned by `.ai/configuration.md`.
- Evidence: `composer test:generated-s3` runs real SQLite, SDK synthetic results, subprocess CLI/source controls and actual SDK/Guzzle loopback faults. It makes no AWS request. Those offline tests and the complete framework `composer check` suffice for reference completion under #109. Real-AWS and deployment verification are deferred until application adoption; `file-transfers:s3:verify` intentionally fails until those resource-bound modules exist and pass. Production rate/cost/egress/audit/alert/incident owners and restoration proof remain adoption requirements.
