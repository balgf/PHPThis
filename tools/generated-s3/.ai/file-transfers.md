# Generated inventory and audio policy

`REFERENCE_ONLY(AMAZON_S3_ADR053, GENERATED_INVENTORY_ADR068)` — offline reference; no adopted AWS or production deployment. This is the single writable application storage/lifecycle policy. Contract 22 and `docs/file-transfers/generated-exports.md` own the framework extension.

- Operation: tenant-free, single-host trusted CLI inventory export and fixed test tone. The sole `console.php` accepts `generate` or `generate-test-tone` without arguments, and `verify`, `reconcile-one` or `expire-one` with one exact export ID. Success is one JSON line with command and outcome; errors are the existing generic JSON/exit contract. HTTP/browser routes, upload fields, PHP temporary uploads, browser authentication and CSRF, tenants, redirects and external consumers are not applicable. The supervisor supplies workload authority; no unauthenticated HTTP adaptation is implied.
- Source: private preprovisioned SQLite `inventory`, at most 1,000 typed rows, one SELECT LIMIT 1001, ordered SKU, integer quantity. Fixed CSV header/columns/LF; 1–65,536 generated opaque bytes. No active parsing or downstream spreadsheet safety guarantee.
- Test tone: accepted by the maintainer on 2026-10-17 for #143. `TEST_TONE_PCM16_V1` is exactly 32,044 bytes: one second of mono 16 kHz signed 16-bit PCM RIFF/WAVE, a 16-byte fmt chunk then data, fixed 16-sample rounded 1 kHz sine cycle repeated 1,000 times, peak magnitude 4,096. This fits #142's accepted WAV representation. No parameter, input file, payload path, metadata or source media is accepted. The intended use is an explicitly selected audio-path test; no audio is played, and there is no calibration, hearing-safety or playback claim.
- Generation: after writer configuration/CA/lifetime validation but before SQLite or S3-client construction, `TestToneProducer` runs one fixed `worker/test-tone.php` with absolute PHP_BINARY, array-form execution, `-n`, empty environment argument, closed stdin and code-owned worker directory. The worker loads no SDK/bootstrap, credentials or configuration. It performs fixed work with a 16 MiB PHP allocation limit and 2s PHP execution timer. Parent wall deadline is 3s, stdout 32,044 bytes and stderr 1,024 bytes, each with one overflow-detection byte. Drain both concurrently. TERM/250ms then KILL/1s cleanup must confirm stop before reap or acceptance. Nonzero exit, diagnostics, partial/excess/mutated output, timeout or unresolved cleanup fails before reservation/S3. Only clean EOF and the exact reviewed output digest create `TestToneBytes`; the digest is the public synthetic fixture identity, distinct from private retained-object metadata.
- Producer ownership: no payload disk staging or fabricated PHP upload. Reject missing, non-regular, symlinked or hardlinked worker files; deployment keeps the release and working directory immutable with unrelated writers excluded. The trusted worker creates no descendants; startup disables subprocess functions. This is bounded trusted-code execution, not an OS sandbox or total RSS limit. The external supervisor owns the complete parent/child scope, including parent death, and must verify an OS memory bound. No process result/diagnostic or generated bytes enter console output.
- Storage: actual regional Amazon S3 only; SDK 3.392.1, Guzzle 8.0.2, PSR-7 3.1.0 and the committed complete lock. All ADR 053 bucket/KMS/IAM/TLS/audit constraints apply. Their actual resource identities and deployment facts are currently unverified.
- Ownership: random 32-lowercase-hex ID, fixed private-documents/v1 key, never reused. Metadata binds size, SHA-256 and target fingerprint (bucket/region/account/KMS), timestamps, state, exact non-null VersionId and persisted delete-attempt count. Metadata loss is an incident; objects are never adopted from broad listings.
- Admission: reserve metadata before Put. At most 32 live/reserved objects, 2 MiB, 256 total identities. Failed collisions and proved pre-send failures release live quota; ambiguity retains it. Deleted/failed rows remain as ownership tombstones. No history recycling or automatic migration.
- Content: `OPAQUE_BYTES`, fixed application/octet-stream and profile metadata. Put uses conditional create, STANDARD, SSE-KMS with bucket keys disabled and explicit owner/checksum. Exact retained facts are checked at Head and Get, including absent storage/archive/expiry and encoding/range/delete-marker fields.
- State: pending → stored → accepted; failed is only proved no-object/collision. Uncertainty retains pending/stored/reconciliation_required. A collision is never inspected. Empty uncertain-write listing is unresolved. One exact version plus valid Head can reconcile acceptance. Marker/sibling/multiple/truncated/unknown ownership is an incident.
- Producer recovery/compatibility: pre-reservation failure discards memory and leaves no object; retry is a fresh explicit command after cleanup. After reservation, the existing ambiguity/never-repeat-Put rules apply. CSV and tone share the same opaque ledger, quotas and commands; no schema or metadata migration is needed. Internal reads assert integrity, not a producer/format from an ID. Generator changes require a new reviewed definition/evidence; previously retained opaque objects keep their recorded eligibility and are never rewritten or automatically regenerated. This adds no general S3 inspected-content, playback, delivery or external-service operation and leaves Contract 26/Profile 4 unchanged.
- Expiry: created + 86,400 seconds, checked before and after read. Expiry disables serving independently of cleanup. Persist deletion_pending and attempt count before exact-version Delete. At most two attempts across restarts; verify absence before deleted/release. No fixed physical deletion deadline during outage.
- Concurrency/durability: private precreated 0700 root, 0600 SQLite/lock, current non-root UID, regular non-symlink/non-hardlinked files, unrelated writers excluded. Same-host flock, nonblocking exclusive mutation/shared read through validation. SQLite DELETE journal and FULL synchronous, local durable filesystem; backups/restore/loss recovery require operator review. No multi-host guarantee.
- Bounds: memory-only staging/read sink, 64 KiB data / 16 KiB control responses, PHP 64 MiB; deployment OS memory bound still to be measured. Connect 2s, operation 10s, retries/redirects/decompression off, at most four remote calls and external 60s command deadline. No retry loop, default credential chain or disk payload staging.
- Read errors: missing, permission, timeout, partial bytes, corrupt checksum or retained-fact mismatch return no bytes. Close all handles; no fallback/latest-version read.
- Process authority: writer Put/Head, reader GetVersion, reconciler ListVersions/Head, deletion ListVersions/Head/DeleteVersion. KMS actions and exact resource grants need real AWS verification. No DeleteObject-without-version or bucket/key administration. Distinct inputs and fresh short-lived tuple per process are owned by `.ai/configuration.md`.
- Evidence: `composer test:generated-s3` runs real SQLite, SDK synthetic results, real producer/console faults and SDK/Guzzle loopback transport. Python independently computes all tone samples and WAV bytes; tests prove output/process limits, credential exclusion, invalid worker paths, zero protected effects on generator failure, supervised interruption, shared CSV/WAV capacity, ambiguous writes, metadata recovery and exact reads/deletion. It makes no AWS request. Those offline tests and the complete framework `composer check` suffice for reference completion under #109/#143. Real-AWS and deployment verification are deferred until application adoption; `file-transfers:s3:verify` intentionally fails until those resource-bound modules exist and pass. Production rate/cost/egress/audit/alert/incident owners and restoration proof remain adoption requirements.
