# Common-change calibration v2

This is a new six-run operational calibration following [calibration v1](calibration-v1.md). It uses the same revision-2 task fixtures, original functional prompts, private holdouts, first-round order, model, reasoning setting, images, dependency identities, and one-dollar per-run token-charge ceiling. It changes the cumulative allowance and the separately retained working-instructions suffix. Historical attempts, policies, reports, and unresolved reservations remain unchanged. Neither calibration supplies correctness rates for the sixty-trial comparison.

Each run requests `gpt-5.4-2026-03-05`, high reasoning, standard service, and permits 1,000,000 cumulative input/output tokens, 1,200 seconds, 4 MiB command output, and zero post-scoring repair turns. The host counts every request before dispatch and rejects input above 200,000 tokens with `model_input_limit`. The unchanged monetary policy also limits a single reservation to at most 66,666 output tokens. These bounds keep a request below the 272,000-token pricing tier. Cumulative cached input still counts toward the million-token allowance. This allows repeated context without treating cached input as free.

The fixed standard prices remain $2.50 per million input tokens, $0.25 cached input, and $15 output, reviewed against the [official pricing page](https://developers.openai.com/api/docs/pricing). Integer accounting reserves uncached counted input plus the maximum affordable output before each create, then settles only validated terminal usage. Each run has an independently enforced USD 1.00 ceiling; six fixed starts allocate at most USD 6.00. An ambiguous request retains its token and money reservations and stops subsequent starts. Model-input, cumulative-token, and monetary exhaustion are distinct recorded reasons; a count-only rejection may continue to the next fixed slot only when no reservation remains and cleanup is verified.

The v2 suffix gives concrete discovery commands scoped to application source, tests, evaluation entrypoints, and application context. It directs the agent to read required authority first, follow the installed knowledge map to exact task-specific guides, avoid recursive searches of the entire candidate or vendor/documentation trees, batch focused reads, implement once the relevant contract is understood, and run the public gate promptly. It supplies no solution or private expectation and exempts no mandatory read, protected file, behavior requirement, edit limit, or check. The original source prompt and effective prompt are both retained and hash-bound.

Use the same `calibration-prepare`, `calibration-run`, and `calibration-report` commands with shared profile condition `calibration-v2`, fixed policy kind `calibration-v2`, and `request_input_tokens: 200000`. Execution explicitly selects the 1,000,001 compaction threshold, beyond the entire cumulative allowance; no compaction operation is authorized. V1 keeps its 200,000-token policy and 200,001 threshold; ordinary smoke/comparison behavior keeps its existing allowance and arguments. Intermediate unreviewed spending-mode budgets between 200,000 and 1,000,000 are rejected.

Attempt, score, and report kinds use `calibration-attempt-v2`, `calibration-score-v2`, and `calibration-report-v2`, with `comparative_claims: false`. A new campaign identity and separately verified six preparations are mandatory. Generation, freeze, private scoring, retention, and cleanup use the existing controller path. No automatic retry, resume, replacement attempt, or private-feedback repair occurs. Reporting preserves failed and unfinished outcomes, unknown accounting, and pending accountable review.
