# Metadata document reference policy

`REFERENCE_ONLY(AMAZON_S3_METADATA_UPLOAD)`; `OPAQUE_BYTES`. The [operation owner](../../../docs/file-transfers/metadata-uploads.md) defines fields, normalization, status mapping and lifecycle. This record names this reference's application facts; it establishes no deployed adoption.

## Composition and authority

The only deployed HTTP candidate is `public/index.php`, composed by `http.php`. It uses the canonical reader, finite `POST /documents` route and explicit action-specific `DocumentUploadPolicy`. The checked policy denies every request. Production Bearer verification is deferred to adoption. Tenant resolution and CSRF are inapplicable to this tenant-free non-browser operation; cookie/browser adoption needs its own policy. No download route or public metadata response exists.

`DocumentOwner` comes only from accepted policy or the authorized maintenance operator. The operator supplies exact document and owner identifiers to `console.php`; it is not a request-driven subprocess. Writer, reconciler and deletion roles share one private SQLite/lock authority but receive separate least-privilege AWS identities. Writer permits conditional Put and exact-version Head; reconciler permits constrained ListObjectVersions and Head; deletion permits constrained listing, Head and exact-version Delete. KMS permissions, CloudTrail, cost controls and target resources follow the S3 owner and require actual adoption evidence.

## Configuration and process bounds

`src/ReferenceEnvironment.php` is the sole environment reader. Three factories return `WriterConfiguration`, `ReconcilerConfiguration` and `DeletionConfiguration`. Each uses its own literal `PHPTHIS_DOCUMENT_WRITER_`, `PHPTHIS_DOCUMENT_RECONCILER_` or `PHPTHIS_DOCUMENT_DELETION_` prefix with the exact suffixes `ROOT`, `BUCKET`, `REGION`, `ACCOUNT`, `KMS`, `CA_PATH`, `CA_SHA256`, `ACCESS_KEY`, `SECRET`, `TOKEN`, `EXPIRES`. `EXPIRES` is a ten-digit epoch-second string. No fallback, refresh, shared profile file, secret lookup or automatic dotenv is permitted. A supervisor supplies a complete selected tuple at process start and restarts for rotation; values never enter reports or context.

`S3Settings` validates the fixed bucket/region/account/customer-managed KMS ARN, canonical absolute root and explicit temporary credential tuple. It verifies a regular nonsymlink 1-byte–1-MiB CA bundle against its SHA-256 and a remaining credential lifetime greater than 120 seconds and at most 12 hours. `Composition.php` fixes HTTPS, certificate verification, no proxy/redirect/cookie/retry/discovery and 2-second connect/10-second operation limits. Its SDK/Guzzle versions come from the existing generated recipe's lock.

Configure the HTTP SAPI with a 64 MiB memory ceiling (the console sets it explicitly); an adopting supervisor supplies a 60-second wall deadline and one active mutation, plus bounded invocation rate. Each operation uses at most four S3 calls, 16 KiB control-response memory and 16 SQL statements with a 16-fingerprint trace. Native HTTP limits come from the operation guide; effective request parsing, upload temporary directory, private native error logging and all E_ALL bits are target-SAPI adoption evidence. Timeout/termination after reservation retains uncertain ownership. This same-host flock policy does not provide distributed coordination.

## Private data and maintenance

Provision a dedicated canonical owner-only directory (0700), `documents.sqlite` and `documents.lock` (regular, nonsymlink, singly linked, same UID, 0600). `DocumentRoot` verifies them before use; HTTP never creates or repairs them. Use the literal schema fixture through an authorized non-HTTP provisioning/migration path. SQLite is the selected engine, with synchronous FULL, zero busy timeout and no unrelated writers. Verify filesystem durability, database journal permissions, backups and private upload temporary storage before deployment. Native uploads are transient; no permanent local object copy is retained.

The row atomically binds owner, label/note, digest, size, target, state, exact version and expiry. Global 32-object/2-MiB, per-owner eight-object/512-KiB and 256-identity history ceilings include unresolved reservations. History exhaustion stops new work. Label/note stay private through pending/reconciliation/deletion uncertainty and are cleared on committed failed/deleted states. The 24-hour deadline stops eligibility; outages can retain physical bytes and descriptive metadata longer. The operator owns bounded recovery, authorized backup retention/deletion and restoration after row loss. No automatic discovery, tombstone recycling or history pruning is implemented.

The sole commands are `reconcile-one <id> <owner>` and `expire-one <id> <owner>`. Expected outcomes are `not_due`, `reconciled`, `unresolved`, `deleted`, `already_deleted`: exit 0 with one LF-terminated JSON stdout object containing only `command`, `outcome`. Unknown command or invalid arguments exit 2 with one generic stderr error; operational failures exit 1 with `command_failed`. No arguments or identifiers are echoed. Scheduled cadence, missed-run and catch-up policy are inapplicable; an adopter owns external supervision. Authoritative metadata and persisted delete attempts bound recovery across invocations.
