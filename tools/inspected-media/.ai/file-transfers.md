# Catalog PNG reference policy

This is the reference's single file-transfer policy. `LOCAL_ADR026`, `INSPECTED_CONTENT`, `REFERENCE_ONLY(INSPECTED_PNG)`. The maintainer approved the PNG, isolation, quarantine, 24-hour expiry and reinspection proposal for #108 on 2026-10-15. This disposable single-host reference is not a production adoption record.

## Operation and inspection

`POST /catalog-images` accepts exactly one `image` file and no fields/query parameters. The native multipart ceiling is 2 MiB; actual/reported file bytes must agree and be 1–1,048,576 inclusive. Preserve PHP's documented normalized-input limitations, including duplicate scalar collapse and malformed-part tolerance. `PendingImageUpload` checks native status and `is_uploaded_file`; client filename and MIME are unused. A successful `move_uploaded_file` transfers ownership from PHP to the application, which verifies private regular-file type, size and SHA-256 before recording `pending` and returning `202`. The PHP temporary path never enters metadata or later work.

The accepted inspection subset is 8-bit, non-interlaced RGB/RGBA PNG, 1–1,024 pixels per dimension, at most 64 chunks, with only `IHDR`, consecutive `IDAT`, and terminal `IEND`. Ancillary metadata, palette, grayscale, other bit depths, interlacing, animation, other formats and trailing bytes are rejected. The PHP envelope/CRC check requires exactly `(width × channels + 1) × height` decompressed bytes, legal row filters and complete consumption of one zlib stream. The first inflate is capped at expected bytes plus one; accepted scanlines cannot exceed 4,195,328 bytes. Then `pngcheck -q` must pass on the same bytes. There are no derived files, antivirus signatures, malware-safety or arbitrary downstream-decoder guarantees.

`Dockerfile` pins PHP 8.4.26, pngcheck 4.0.1 source `861c978c3b1bac93659202fd25b9b76bc852eee1`, and zlib 1.3.2, with hash-verified downloads. PHP links the selected zlib and pngcheck links it statically. `inspection-policy.json`, the explicit `InspectionDefinition::sources()` inventory and the immutable built image ID define acceptance. Every tool/build dependency/configuration/signature-applicability/format/application-policy change requires a new definition and reinspection. This reference has no external inspection service or third-party byte retention/residency/credential policy.

## Authority, admission and storage

The HTTP path is `authenticate -> authorize named upload/read -> admission lock -> operation input/provenance -> atomic quota reservation -> storage`. The reference is tenant-free, principal-bound and stateless; there is no cookie/session authority, so CSRF is inapplicable to this selected machine profile. A browser/cookie adopter must add its established CSRF path. `public/index.php` visibly injects deny-all policies. Only the disposable front-controller copy created by `run.py` injects `tests/SyntheticPolicy.php`, an I/O-free fixture policy. Those credentials and policies are not authentication infrastructure. Reads authorize before storage lookup, additionally bind `owner_id` in SQL, and return the same private `404` for missing, other-owner, unaccepted, outdated or expired records.

Provisioning pre-creates a non-symlink private root, `objects/`, `catalog.sqlite` and `catalog.lock`. Directory/file modes are `0700`/`0600`, owned by the process identity; ACL is NONE in the disposable fixture. The root is outside the HTTP document tree. Handling never creates, chmods, repairs or replaces that root. Each retained identity gets one private directory and fixed `content` name; unrelated writers are excluded. SHA-256 is private metadata, computed after move and checked before inspection, after inspection and before response selection. It is never returned publicly. Digest mismatch stops acceptance/serving. There are no replicas, backups, restores, holds or digest-algorithm transitions in this disposable reference; adopting any requires a reviewed lifecycle.

One nonblocking same-host `flock` serializes all mutations. Downloads hold the shared lock through the full `ResponseEmitter` call. It excludes cooperating cleanup, reinspection and definition changes for the entire path-selection/emission interval. A digest does not replace this lock or exclusive-writer deployment invariant; rogue writers and network/shared filesystems are outside the proof. Lock contention is generic `503`; there is no waiting or HTTP retry.

An atomic conditional SQLite insert reserves at most 32 retained files and 32 MiB before filesystem work. Pending, rejected, error and incomplete reservations all count. With a 1 MiB per-file bound, the byte ceiling also follows from the count ceiling. There is no count-then-write gap. There is one global catalog, so tenant quotas are inapplicable; each principal shares the global ceiling. One inspection starts per second at most, with one worker holding the mutation lock throughout. A backwards clock stops new starts until time catches up. A client retry creates a new reservation; after an ambiguous `202`, there is no implicit deduplication or success claim. The original item remains governed by quota/expiry.

SQLite is application-private, unqualified `main`, with no attached databases or SQL namespace discovery. HTTP/worker SQL uses `Connection` with fresh budgets/traces (8/16 statements). The fixture's finite DDL in `tests/Fixture.php` owns schema creation; HTTP and the application console never provision schema. SQLite file/process authority supplies no separate roles or grants and cannot enforce statement-level least privilege. The deployment operator owns provisioning and release activation, and must isolate these identities before production adoption.

## Worker and failure lifecycle

`images:inspect-one` selects zero/one unexpired eligible record in `(created_at, image_id)` order. It commits `inspecting`, a random private container token, the current definition and attempt number before external work. It passes one bounded immutable byte string over stdin to a fresh container; no storage/source/credential/socket mounts enter it. The trusted CLI supervisor alone has local Unix Docker-daemon authority; HTTP has none by design and deployment must enforce that OS separation.

The inspector runs as UID/GID 65534, network none, root filesystem read-only, capabilities dropped, no-new-privileges, eight PIDs, 64 MiB memory including its swap allowance, one CPU and two CPU seconds. PHP is limited to 32 MiB. The supervisor has a ten-second inspection deadline and an 8 KiB cap on each output stream; its separate cleanup calls each have a three-second deadline. Parser diagnostics and Docker logs are discarded. Only exact finite protocol output and exit status can produce acceptance. Nonzero/invalid output, unavailable tools, timeout, resource termination, digest mismatch or unresolved container cleanup yields `scanner_error`, never acceptance. The whole command also needs an independent external job deadline because native process creation/reaping and an unresponsive OS/daemon cannot be fully bounded by PHP.

Promotion to `accepted` follows successful integrity checks, both parser checks and verified container absence. `reserved`, `pending`, `inspecting`, `rejected`, and `scanner_error` are non-serving. Inspection interruption leaves its committed record non-serving; `images:reconcile-one` takes the same exclusive lock, removes that exact labeled container, then records `scanner_error`. An operator may invoke `images:retry <id>` for an unexpired error, with at most two attempts per file/definition. There is no implicit retry. A new definition resets the attempt allowance and reinspection eligibility; rejected content is reconsidered only under a new definition.

`images:activate-definition` explicitly changes the selected definition under the mutation lock. Old acceptance is immediately ineligible. HTTP also requires the active source fingerprint to match the running code/policy, preventing a code change from inheriting an old acceptance. Repeating the current activation is a no-op; retired definitions cannot be reactivated, including during rollback. A rollback needs a new reviewed definition (for example a new image revision), with fresh reinspection. The registry is bounded to 32 definitions for this disposable catalog; exhaustion fails before activation and needs a separately reviewed data-lifecycle change. The same bounded selection/rate handles reinspection; interrupted work is recovered before retry. Only a matching completed inspection promotes the item under the new definition. The maintainer owns tool/policy review and reinspection completion; the operator owns deployment, recovery and capacity incidents.

Serving expires exactly 86,400 seconds after ingestion, including rejection/error retention. `images:expire-one` deletes at most one expired item's exact file and directory and then removes its quota record. The operator schedules that one-pass command every second and alerts on nonzero exits or overdue retained items. Physical deletion is supervised work, not an exact-time guarantee during outage or failed cleanup. Partial cleanup retains the reservation; unknown files, symlinks and wrong modes are not recursively removed. A reserved move interrupted before or after storage is removed by `images:reconcile-one`; no incomplete upload is salvaged into acceptance. Both commands require supervision; an unresolved oldest item can block their ordered progress and needs operator recovery.

Accepted download uses fixed `image/png`, `attachment; filename="catalog-image.png"`, exact length, private/no-store, `nosniff`, and `Accept-Ranges: none`. A range request gets the full `200`. The existing pre/post-response-start emission rules apply, with no replacement after response start. Client receipt is not proved.

## Evidence and adoption limits

`php ../test-inspected-media.php` proves bounded parsing, policy order, local lifecycle, lock behavior, integrity and CLI/source failures without Docker. `python3 run.py` adds the exact real tools, OS resource failures, native HTTP upload provenance, quarantine/promotion, metadata distrust, owner isolation, definition updates, outage/retry, quota and deletion; `evidence.json` records dated versions and source hashes. The dedicated CI job reruns the real proof on Linux. Root `composer check` remains mandatory.

The fixture uses the built-in PHP server on an ephemeral loopback port, explicit automatic POST parsing off, uploads on, upload progress/encoding translation off, a private effective `upload_tmp_dir`, 32 MiB PHP memory and a 15-second PHP execution setting. It asserts temporary cleanup and stored modes. It supplies no production proxy, TLS, raw-part strictness, upload timeout, request-rate/egress policy, byte/inode capacity monitor, no-execute volume, ACL/mandatory-access-control rule, inability of an owner to chmod its root, multi-host filesystem, identity provider or secret-rotation evidence. It does not inject real disk/inode exhaustion, power loss or filesystem durability failures. A production adopter must complete those existing `LOCAL_ADR026` obligations; this reference does not weaken the profile.
