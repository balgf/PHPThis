# Catalog PNG/JPEG/MP4/WAV reference policy

This is the reference's single file-transfer policy. `LOCAL_ADR026`, `INSPECTED_CONTENT`, `REFERENCE_ONLY(INSPECTED_PNG)`, `REFERENCE_ONLY(INSPECTED_JPEG)`, `REFERENCE_ONLY(INSPECTED_MP4)`, `REFERENCE_ONLY(INSPECTED_WAV)`. The maintainer approved the PNG, isolation, quarantine, 24-hour expiry and reinspection proposal for #108 on 2026-10-15. The maintainer approved the separate JPEG profile, shared lifecycle and retained-format migration for #140 on 2026-10-16. The maintainer approved the separate MP4 profile, FFmpeg decoder, shared lifecycle and table-rebuild migration for #141 on 2026-10-16. The maintainer approved the separate WAV profile, structural PHP inspection and retained-format migration for #142 on 2026-10-17. This disposable single-host reference is not a production adoption record.

## Operation and inspection

`POST /catalog-images` fixes PNG; `POST /catalog-jpeg-images` fixes JPEG. `POST /catalog-video-clips` fixes MP4 and `POST /catalog-audio-clips` fixes WAV; both accept exactly one `clip`. The image routes each accept one `image`. All reject fields/query parameters. The legacy `image_id` response key and catalog identities are retained. The native multipart ceiling is 2 MiB; actual/reported file bytes must agree and be 1–1,048,576 inclusive for PNG/JPEG/MP4, or 46–320,044 inclusive for WAV. These format-specific bounds apply before reservation. Preserve PHP's documented normalized-input limitations, including duplicate scalar collapse and malformed-part tolerance. `PendingImageUpload` checks native status and `is_uploaded_file`; client filename and MIME are unused. A successful `move_uploaded_file` transfers ownership from PHP to the application, which verifies private regular-file type, size and SHA-256 before recording `pending` and returning `202`. The PHP temporary path never enters metadata or later work.

The PNG inspection subset remains 8-bit, non-interlaced RGB/RGBA PNG, 1–1,024 pixels per dimension, at most 64 chunks, with only `IHDR`, consecutive `IDAT`, and terminal `IEND`. Ancillary metadata, palette, grayscale, other bit depths, interlacing, animation, other formats and trailing bytes are rejected. The PHP envelope/CRC check requires exactly `(width × channels + 1) × height` decompressed bytes, legal row filters and complete consumption of one zlib stream. The first inflate is capped at expected bytes plus one; accepted scanlines cannot exceed 4,195,328 bytes. Then `pngcheck -q` must pass on the same bytes. There are no derived files, antivirus signatures, malware-safety or arbitrary downstream-decoder guarantees.

`CATALOG_JPEG_BASELINE_V1` permits baseline sequential Huffman DCT (SOF0), eight-bit YCbCr with exactly IDs 1/2/3, Y sampling 1×1/2×1/2×2 and Cb/Cr 1×1. One interleaved scan uses Ss=0, Se=63, Ah=Al=0. One first APP0 is JFIF 1.01/1.02, density unit 0/1/2 with positive 16-bit densities, no thumbnail. The exact sequence is SOI, APP0, DQT(s), SOF0, DHT(s), SOS, entropy and EOI at EOF, with at most 32 length-bearing segments. DQT uses nonzero eight-bit values and IDs 0–3; DHT uses DC/AC IDs 0–3 with 1–256 declared symbols. References must exist and tables cannot be redefined. Entropy permits FF00 stuffing only before final EOI. All other APP/COM metadata (including EXIF/ICC/XMP), progressive/grayscale/RGB/CMYK/YCCK/arithmetic/lossless variants, other precision/sampling, restart markers, marker padding, leading/trailing bytes and concatenated images are rejected.

JPEG dimensions are 1–1,024 per axis, at most 1,048,576 pixels and 3,145,728 RGB pixel bytes. `BoundedJpeg` checks the finite envelope before `djpeg -strict -maxscans 1 -maxmemory 16M -rgb -pnm -outfile /dev/null` checks full entropy/table validity. The decoder workspace flag is 16,000,000 bytes; it is not the whole-process memory bound. Structural policy failures are `rejected`. Every nonzero/signal decoder result is `scanner_error`, including corrupt entropy, because exit status cannot establish whether resources or content caused failure. Diagnostics/output are discarded; successful decoder whitespace on stderr is not interpreted. No stripping, orientation correction, color conversion or normalization occurs. Only the original bytes are retained. Ordinary EXIF-bearing camera images and progressive web JPEGs are outside this operation. Later decoders require their own review/isolation.

`CATALOG_MP4_AVC_BASELINE_V1` accepts a deliberate silent catalog export, 1–1,048,576 bytes. Its non-fragmented 32-bit ISO BMFF structure is exactly `ftyp`, `moov`, optional empty `free`, terminal `mdat`; brand is `isom` minor 512 with `isom/iso2/avc1/mp41`. There is one enabled video track, one `avc1` description and one contiguous chunk covering all media bytes. The finite `mvhd/trak/tkhd/mdia/mdhd/hdlr/minf/vmhd/dinf/dref/stbl/stsd/stts/[stss]/stsc/stsz/stco` hierarchy has no recursive discovery. Require one self-contained empty `url ` reference, zero timestamps, identity matrices, `und` language, fixed `VideoHandler` and empty/`Lavc libx264` labels, square `pasp`, fixed-size numeric `btrt` and only the optional exact empty FFmpeg metadata scaffold. Unknown boxes, other tracks, external references, fragmentation, edits, encryption, rotation, 64-bit/open-ended sizes, multiple chunks and trailing bytes are rejected.

AVC uses exact `avcC` prefix `01 42 c0 1e ff e1`, Constrained Baseline level 3.0, one SPS/PPS of at most 1,024 bytes each, matching IDs, 1–4 references, picture-order count 0 or 2, no frame-number gaps/CABAC/interlacing. Display dimensions are even 2–640 × 2–480; coded dimensions are also at most 640×480 and the SPS crop must match the container before decoding. Remaining bounded codec control fields, including VUI, belong to the decoder. The one constant sample delta gives integer 1–30 fps, a positive duration through 10 seconds and 1–300 frames; media timescale is 1–90,000 and movie timescale 1,000 with matching rounded duration. Each sample is 5–262,144 bytes and exactly one four-byte-length-prefixed VCL NAL with header `41`, `61` or `65`; sync entries match IDR samples. No SEI, in-band parameter-set changes, audio, B frames or other codecs/profiles are accepted. This is not general camera-video compatibility.

`BoundedMp4` validates the envelope and parameter-set resource declarations before `Mp4Decoder` invokes pinned FFmpeg 9.0.2 `ffprobe` with a fixed argument array. The build enables only the MOV demuxer, H.264 parser/decoder and pipe protocol, with network, autodetection, other formats/codecs, assembly, threads and unused libraries off. Official source SHA-256 is `8c3850283eb25fa026482078a04051e0be17347b09ef81a0849bec15a96e002e`. The LGPL notice is retained in the image. Pipe-only input, external/absolute references off, strict error detection, one thread, 307,200 coded pixels and an 8 MiB individual-allocation cap are explicit. Every sample must produce exactly one matching progressive eight-bit `yuv420p` I/P frame, with matching timestamp/dimensions and no frame side data. Nonzero exit, warning diagnostics, incomplete/invalid/disagreeing reports or resource failures are `scanner_error`; envelope failures are `rejected`. The eight-second decoder deadline and live stdout/stderr caps of 65,536/8,192 bytes sit inside the unchanged container/outer limits. At most 138,240,000 cumulative decoded pixel bytes are accepted; the container, not that total or `max_alloc`, bounds peak memory. No decoded output, re-encoding, metadata stripping or transformed file is retained. Original bytes alone are served after verified full decoding and cleanup.

`CATALOG_WAV_PCM16_MONO_16KHZ_V1` accepts short catalog voice clips as little-endian RIFF/WAVE with exactly one 16-byte `fmt ` chunk followed by one terminal `data` chunk. Require PCM tag 1, one channel, 16,000 samples/second, 16-bit signed samples, block alignment 2 and byte rate 32,000. Actual bytes are 46–320,044 inclusive; data bytes are even and 2–320,000, giving 1–160,000 sample frames and a positive duration through ten seconds. Both RIFF/data lengths must match actual bytes. Reject RIFX/RF64/BW64/Wave64, extensible/float/compressed encodings, other rates/channels/depths, extended format chunks, duplicate/reordered/unknown chunks, nested lists, metadata, padding, concatenated files and trailing bytes.

`BoundedWav` performs structural PCM inspection inside the existing isolated PHP process. It bounds actual bytes before comparing the complete fixed header, derives expected lengths from that bounded size and verifies complete sample alignment. Every signed 16-bit pattern is a valid PCM sample, so there is no compressed bitstream or expansion stage and no additional decoder process. The parser retains only the frame count; it creates no sample array. Structural failures are `rejected`; process/resource/protocol/cleanup uncertainty is `scanner_error`. No new binary or dependency is added. Original bytes alone are retained. This establishes representation/resource policy, not intelligibility, sound quality, malware absence, hidden-information removal or downstream-player safety. Playback, transcription, transformation and S3 inspection are separate work.

`Dockerfile` pins PHP 8.4.26, pngcheck 4.0.1 source `861c978c3b1bac93659202fd25b9b76bc852eee1`, and zlib 1.3.2, with hash-verified downloads. PHP links the selected zlib and pngcheck links it statically. The JPEG tool is libjpeg-turbo 3.2.0, official source archive SHA-256 `6f30092cef9fb839779646608f4ee14ae3cbac989c47fa05e841b0841f09878e`, statically linked with SIMD, arithmetic coding, TurboJPEG and Java interfaces disabled. CMake 3.25.1-1 is confined to the build stage; acquisition uses the named Debian repositories and official source URLs, while compilation/tests and inspection have no network. The image build runs the selected libjpeg upstream regression suite; MP4 decoder behavior is verified by the real reference fixtures. `inspection-policy.json`, the explicit `InspectionDefinition::sources()` inventory and the immutable built image ID define acceptance. Every tool/build dependency/configuration/signature-applicability/format/application-policy change requires a new definition and reinspection. This reference has no external inspection service or third-party byte retention/residency/credential policy.

## Authority, admission and storage

The HTTP path is `authenticate -> authorize named upload/read -> admission lock -> operation input/provenance -> atomic quota reservation -> storage`. The reference is tenant-free, principal-bound and stateless; there is no cookie/session authority, so CSRF is inapplicable to this selected machine profile. A browser/cookie adopter must add its established CSRF path. `public/index.php` visibly injects deny-all policies. Only the disposable front-controller copy created by `run.py` injects `tests/SyntheticPolicy.php`, an I/O-free fixture policy. Those credentials and policies are not authentication infrastructure. Reads authorize before storage lookup, additionally bind `owner_id` and the trusted route's expected `format` in SQL, and return the same private `404` for missing, other-owner, unaccepted, outdated, wrong-format or expired records.

Provisioning pre-creates a non-symlink private root, `objects/`, `catalog.sqlite` and `catalog.lock`. Directory/file modes are `0700`/`0600`, owned by the process identity; ACL is NONE in the disposable fixture. The root is outside the HTTP document tree. Handling never creates, chmods, repairs or replaces that root. Each retained identity gets one private directory and fixed `content` name; unrelated writers are excluded. SHA-256 is private metadata, computed after move and checked before inspection, after inspection and before response selection. It is never returned publicly. Digest mismatch stops acceptance/serving. There are no replicas, backups, restores, holds or digest-algorithm transitions in this disposable reference; adopting any requires a reviewed lifecycle.

One nonblocking same-host `flock` serializes all mutations. Downloads hold the shared lock through the full `ResponseEmitter` call. It excludes cooperating cleanup, reinspection and definition changes for the entire path-selection/emission interval. A digest does not replace this lock or exclusive-writer deployment invariant; rogue writers and network/shared filesystems are outside the proof. Lock contention is generic `503`; there is no waiting or HTTP retry.

The reservation persists the code-owned `CatalogImageFormat` (`png`/`jpeg`/`mp4`/`wav`); filenames/MIME never choose it. An atomic conditional SQLite insert shared across all four upload routes reserves at most 32 retained files and 32 MiB before filesystem work. Pending, rejected, error and incomplete reservations all count. With a 1 MiB per-file bound, the byte ceiling also follows from the count ceiling. There is no count-then-write gap. There is one global catalog, so tenant quotas are inapplicable; each principal shares the global ceiling. One inspection starts per second at most, with one worker holding the mutation lock throughout. A backwards clock stops new starts until time catches up. A client retry creates a new reservation; after an ambiguous `202`, there is no implicit deduplication or success claim. The original item remains governed by quota/expiry.

SQLite is application-private, unqualified `main`, with no attached databases or SQL namespace discovery. HTTP/worker SQL uses `Connection` with fresh budgets/traces (8/16 statements). The fixture's finite DDL in `tests/Fixture.php` owns schema creation; HTTP and the application console never provision schema. SQLite file/process authority supplies no separate roles or grants and cannot enforce statement-level least privilege. The deployment operator owns provisioning and release activation, and must isolate these identities before production adoption.

## Worker and failure lifecycle

`images:inspect-one` selects zero/one unexpired eligible record in `(created_at, image_id)` order. It commits `inspecting`, a random private container token, the current definition and attempt number before external work. It passes the stored finite format explicitly and one bounded immutable byte string through a nonblocking stdin pipe to a fresh container, without a host temporary file; no storage/source/credential/socket mounts enter it. The trusted CLI supervisor alone has local Unix Docker-daemon authority; HTTP has none by design and deployment must enforce that OS separation.

The inspector runs as UID/GID 65534, network none, root filesystem read-only, capabilities dropped, no-new-privileges, eight PIDs, 64 MiB memory including its swap allowance, one CPU and two CPU seconds per process. PHP is limited to 32 MiB. The supervisor has a ten-second inspection deadline and an 8 KiB cap on each output stream; its separate cleanup calls each have a three-second deadline. Parser diagnostics and Docker logs are discarded. Only exact finite protocol output and exit status can produce acceptance. Nonzero/invalid output, unavailable tools, timeout, resource termination, digest mismatch or unresolved container cleanup yields `scanner_error`, never acceptance. The whole command also needs an independent external job deadline because native process creation/reaping and an unresponsive OS/daemon cannot be fully bounded by PHP.

Promotion to `accepted` follows successful integrity checks, the format's recorded structural or full-decoder checks and verified container absence. `reserved`, `pending`, `inspecting`, `rejected`, and `scanner_error` are non-serving. Inspection interruption leaves its committed record non-serving; `images:reconcile-one` takes the same exclusive lock, removes that exact labeled container, then records `scanner_error`. An operator may invoke `images:retry <id>` for an unexpired error, with at most two attempts per file/definition. There is no implicit retry. A new definition resets the attempt allowance and reinspection eligibility; rejected content is reconsidered only under a new definition.

`images:activate-definition` explicitly changes the selected definition under the mutation lock. Old acceptance of all four formats is immediately ineligible. HTTP also requires the active source fingerprint to match the running code/policy, preventing a code change from inheriting an old acceptance. Repeating the current activation is a no-op; retired definitions cannot be reactivated, including during rollback. A rollback needs a new reviewed definition (for example a new image revision), with fresh reinspection. The registry is bounded to 32 definitions for this disposable catalog; exhaustion fails before activation and needs a separately reviewed data-lifecycle change. The same bounded selection/rate handles reinspection; interrupted work is recovered before retry. Only a matching completed inspection promotes the item under the new definition. The maintainer owns tool/policy review and reinspection completion; the operator owns deployment, recovery and capacity incidents.

Serving expires exactly 86,400 seconds after ingestion, including rejection/error retention. `images:expire-one` deletes at most one expired item's exact file and directory and then removes its quota record. The operator schedules that one-pass command every second and alerts on nonzero exits or overdue retained items. Physical deletion is supervised work, not an exact-time guarantee during outage or failed cleanup. Partial cleanup retains the reservation; unknown files, symlinks and wrong modes are not recursively removed. A reserved move interrupted before or after storage is removed by `images:reconcile-one`; no incomplete upload is salvaged into acceptance. Both commands require supervision; an unresolved oldest item can block their ordered progress and needs operator recovery.

The PNG GET route remains `/catalog-images/{image_id:token}`; JPEG uses `/catalog-jpeg-images/{image_id:token}`. Accepted download uses fixed `image/png` with `attachment; filename="catalog-image.png"`, or `image/jpeg` with `attachment; filename="catalog-image.jpg"`, selected only by the trusted route. MP4 uses `/catalog-video-clips/{image_id:token}`, fixed `video/mp4` and `attachment; filename="catalog-clip.mp4"`. WAV uses `/catalog-audio-clips/{image_id:token}`, fixed `audio/vnd.wave; codec=1` and `attachment; filename="catalog-clip.wav"`. All use exact length, private/no-store, `nosniff`, and `Accept-Ranges: none`. A range request gets the full `200`. The existing pre/post-response-start emission rules apply, with no replacement after response start. Client receipt is not proved.

## Retained-format adoption

Drain the catalog HTTP and maintenance processes. Through the application's authorized migration history, add `format TEXT NOT NULL DEFAULT 'png' CHECK (format IN ('png', 'jpeg'))` to the recorded PNG-only baseline. Existing rows remain PNG explicitly; do not infer or reclassify their history. New reservations always bind format. The fixture creates the complete new schema outside HTTP/Composer; `tests/format-migration.php` proves the exact additive statement, rollback and row/constraint preservation only, not a production migration runner or ledger.

For the approved MP4 extension, widen the existing format CHECK to `png/jpeg/mp4` through a reviewed SQLite table rebuild, preserving every other column/constraint/default and all retained values. `tests/mp4-migration.php` proves the documented JPEG-upgrade baseline (including `DEFAULT 'png'`), exact-definition/index/trigger rejection, explicit column copy, rollback after each rebuild stage, unchanged rows/constraints and refusal of a blind rerun. A fresh JPEG fixture without that default requires its own exact baseline. Adopters must verify all dependencies, coordinator and ledger through their recorded migration history; no reference test is an automatic migration command. See the [MP4 guide](../../../docs/file-transfers/inspected-mp4.md).

For the approved WAV extension, widen the format CHECK to `png/jpeg/mp4/wav` inside one explicit transaction. `tests/wav-migration.php` contains two finite CREATE alternatives matching the documented MP4-upgrade baseline with `DEFAULT 'png'` and the fresh MP4 fixture without a default; preserve that distinction, all eleven columns/values and every other constraint. Reject absent transactions, unfamiliar definitions and unreviewed table indexes/triggers before mutation. Tests cover both baseline successes, rollback after each of four stages, row/default/constraint preservation, dependency rejection and blind-rerun refusal. Adopters still verify all dependent objects and their recorded coordinator, ledger and authority. See the [WAV guide](../../../docs/file-transfers/inspected-wav.md).

Deploy coherent schema/code/policy/image, activate its new definition and reinspect before eligible serving. Existing catalog acceptance is unavailable until reinspection; this migration does not promise uninterrupted availability. Keep the existing literal `PHPTHIS_PNG_*` process inputs for the same shared catalog without aliases or extra authority. Rollback drains newly introduced format traffic/maintenance and preserves format, ownership and quota until those objects are resolved. Do not drop format, reinterpret JPEG/MP4/WAV as another format, restore retired acceptance or bypass reinspection. The maintainer owns policy/dependency/security updates; the operator owns migration, deployment and recovery. The [JPEG guide](../../../docs/file-transfers/inspected-jpeg.md) records the exact statement and adoption route.

## Evidence and adoption limits

`php ../test-inspected-media.php` proves bounded PNG/JPEG/MP4/WAV parsing and decoder-report validation, format-row migration, policy order, all four local lifecycles, failed promotion/deletion, lock behavior, integrity and CLI/source failures without Docker. `python3 run.py` adds the exact real tools, OS resource failures, inner MP4 decoder output/deadline/exit faults, native HTTP upload provenance, independent Python WAV writer/reader compatibility, WAV admission bounds, quarantine/promotion, metadata distrust, owner/format isolation, shared quotas, definition updates, outage/retry, quota and deletion; `evidence.json` records dated versions and source hashes. The dedicated CI job reruns the real proof on Linux. Root `composer check` remains mandatory.

The fixture uses the built-in PHP server on an ephemeral loopback port, explicit automatic POST parsing off, uploads on, upload progress/encoding translation off, a private effective `upload_tmp_dir`, 32 MiB PHP memory and a 15-second PHP execution setting. It asserts temporary cleanup and stored modes. It supplies no production proxy, TLS, raw-part strictness, upload timeout, request-rate/egress policy, byte/inode capacity monitor, no-execute volume, ACL/mandatory-access-control rule, inability of an owner to chmod its root, multi-host filesystem, identity provider or secret-rotation evidence. It does not inject real disk/inode exhaustion, power loss or filesystem durability failures. A production adopter must complete those existing `LOCAL_ADR026` obligations; this reference does not weaken the profile.
